page-01–05 Instruction Set（§2.1）#

要指揮電腦的硬體做事，就得用硬體看得懂的語言。這個語言的單字就是 instruction，而一台電腦認得的所有 instruction 合起來叫：

Definition (Instruction set（指令集）)

一個 architecture 認得的全部 instruction。ch01 說的 ISA，核心就是這組 instruction 以及它們的使用規則。

不同電腦的 instruction set 不一樣，但差別比想像中小，比較像方言而不是不同的語言。 原因是各家電腦都用類似的硬體技術、都得提供同一批基本運算，而且設計目標相同：讓硬體和 compiler 都好做，同時兼顧 performance、成本與 energy。 所以學會一種 instruction set，其他的很快就能上手。 早期電腦的 instruction set 很簡單，因為簡單的 instruction set 才好實作；今天很多電腦的 instruction set 依然刻意保持簡單。

這門課用的是 RISC-V：

  • RISC-V 是 UC Berkeley 從 2010 年開始設計的 open ISA——任何人都能免費使用與實作，現在由 RISC-V Foundation（riscv.org）管理；
  • RISC-V 是典型的現代 ISA。類似的 ISA 在 embedded 市場（消費性電子、網通與儲存設備、相機、印表機…）佔很大比例。

page-04 的 MIPS 是 RISC-V 的前輩：1980 年代在 Stanford 發展、後來商業化，設計哲學跟 RISC-V 幾乎一樣，page-84 會拿來對照。 page-05 的 green card 是把所有 instruction 的格式與編碼印在一張卡上的速查表，寫作業時會一直用到。

為什麼每條算術 instruction 都固定三個 operand？加法的自然形式本來就是「兩個輸入、一個輸出」，而且 operand 數量固定，硬體只要處理一種情況。這是課本的第一條設計原則：

Design Principle 1：Simplicity favors regularity

Instruction 長得越規律（例如每條算術 instruction 都固定三個 operand），硬體就越容易實作；硬體越簡單，就能用越低的成本做出越高的 performance。

page-08–11 Register Operands（§2.3）#

page-06 寫 add a, b, c 時，是把 a、b、c 當成 C 程式裡的變數。但真正的 RISC-V instruction 裡沒有「變數」： 算術 instruction 的三個 operand 都必須是 register，寫成 x0 到 x31 這種編號。 所以 compiler 得先決定每個 C 變數放在哪個 register，再用那些 register 寫出 add（例子在 page-11）。

Definition (Register file)

Register 是 processor 裡少量、直接做在硬體裡的高速儲存格，算術 instruction 只能對它們運算。 所有 register 合起來叫 register file（暫存器檔）。RISC-V 有 32 個 register，每個 64 bits，編號 x0 到 x31。

Definition (Doubleword 與 word)

64 bits 的資料叫 doubleword（剛好是一個 RISC-V register 的大小），32 bits 的資料叫 word。

為什麼 RISC-V 只有 32 個 register，不多做一些？這是第二條設計原則：

Design Principle 2：Smaller is faster

Register 的數量越多，register file 就越大，電訊號得跑得越遠，clock cycle 就可能變長。對照之下，main memory 有數十億個位置，所以 main memory 比 register 慢得多。

限制 register 數量的另一個理由會在 page-25 看到：每條 instruction 都得寫出它用到的 register 編號，32 個 register 的編號剛好用 5 bits 表示；register 再多，每個編號就要更多 bits，instruction 會放不下。 page-09 是 MIPS 的版本：同樣 32 個 register，但每個只有 32 bits，assembler 用 $t0–$t9、$s0–$s7 這類名字稱呼它們。

page-12–15 Memory Operands#

Register 只有 32 個，但程式裡有 array、structure（好幾個欄位組成的資料）這種一大包的資料，還有執行中才動態配置的資料， 這些資料塞不進 32 個 register，只能放在 memory。可是 RISC-V 的算術 instruction 只能對 register 運算，所以需要在 memory 與 register 之間搬資料的 instruction：

Definition (Load 與 store)

Load 把資料從 memory 複製到 register，store 把 register 的資料寫回 memory。兩者合稱 data transfer instruction。

Memory 可以想成一個很大的一維 array，而 address（位址）就是這個 array 的 index，從 0 開始。

Definition (Byte addressing)

Byte 是 8 bits。RISC-V 的 memory 是 byte addressed：每個 address 指向一個 byte。 一個 doubleword 有 8 個 byte，在 memory 裡就佔用 8 個連續的 byte，例如 address 16 到 23；這個 doubleword 的 address 是其中最小的那個，也就是 16。 所以相鄰兩個 doubleword 的 address 差 8（0、8、16、24…），不是差 1。

一個 doubleword 由 8 個 byte 組成。其中權重最小的 byte（數字最右邊的 8 bits）叫 least significant byte（LSB）， 權重最大的 byte（數字最左邊的 8 bits）叫 most significant byte（MSB）。這 8 個 byte 在 memory 裡依什麼順序排？規定這個順序的就是 endianness：

Definition (Endianness（位元組順序）)
  • Little endian：LSB 放在最小的 address（也就是這筆資料的 address），越高位的 byte 放在越大的 address。RISC-V 是 little endian。
  • Big endian：MSB 放在最小的 address，越低位的 byte 放在越大的 address。MIPS 傳統上是 big endian。

page-13 的圖以 32-bit 的 0x0A0B0C0D 為例：MSB 是 0A、LSB 是 0D。從低 address 往上，big endian 依序放 0A 0B 0C 0D，little endian 則是 0D 0C 0B 0A。 如果程式總是用整個 doubleword 存取一筆資料，就不必在意 endianness；只有同一筆資料有時被當成整個 doubleword 讀、有時被拆成單一 byte 讀時，byte 的排列順序才會影響讀到的值。

另外，很多 ISA 規定 word 的 address 必須是 4 的倍數、doubleword 必須是 8 的倍數，這叫 alignment restriction（對齊限制）。RISC-V 沒有這個限制。

page-16, 18 Immediate Operands / The Constant Zero#

程式很常用到常數，例如 i += 4。如果只有前面介紹的 add、sub、ld、sd，常數得先存在 memory 裡、每次用到時再 load，每用一次常數就多一條 instruction。 所以 RISC-V 為算術 instruction 提供一種 operand 直接是常數的版本：

Definition (Immediate（立即值）)

直接寫在 instruction 裡的常數 operand。例如 addi x22, x22, 4（add immediate）就是 x22 = x22 + 4。

提供 immediate 是 ch01 的 great idea「make the common case fast」：課本說 SPEC CPU2006 裡超過一半的算術 instruction 都有常數 operand，addi 是最常被執行的 instruction。 （RISC-V 沒有 subi，因為 immediate 可以是負數，addi x5, x5, -1 就是減 1。）

最常用的常數是 0，所以 RISC-V 把 x0 固定成 0：讀 x0 永遠得到 0，寫進 x0 的值會被丟掉。 有了 x0，很多操作不必另外設計 instruction，例如把一個 register 複製到另一個可以寫成 add x10, x11, x0。 page-18 的 MIPS 也一樣，它的 0 號 register 叫 $zero。

負數怎麼表示？ 最直覺的做法是拿一個 bit 當正負號，叫 sign and magnitude。 但 sign and magnitude 有兩個 0（+0 和 −0），加法器也得多一步判斷結果的正負號，所以 sign and magnitude 很快就被淘汰。1965 年以後，所有電腦都改用：

page-20 整理 two’s complement 的幾個性質：

  • Most significant bit 叫 sign bit：1 代表負數，0 代表非負。硬體只要看這個 bit 就知道正負。
  • 非負的數在 unsigned 與 two’s complement 裡的 bit pattern 一模一樣。
  • 正負不對稱：最負的 −2n−1-2^{n-1}−2n−1 沒有對應的正數，所以 −2n−1-2^{n-1}−2n−1 取負號的結果無法表示。
  • 幾個特別的值：0 是全 0，−1 是全 1，最負是 1000…0，最正是 0111…1。

如果運算結果超出能表示的範圍，就叫 overflow（溢位）；例如兩個正數相加，結果的 sign bit 卻變成 1。

取負號（page-21）：每個 bit 反轉，再加 1。 記 xˉ\bar{x}xˉ 為把 xxx 的每個 bit 反轉（0 變 1、1 變 0）。 因為 x+xˉx + \bar{x}x+xˉ 每個 bit 都是 1，也就是 −1-1−1，所以 xˉ+1=−x\bar{x} + 1 = -xxˉ+1=−x。 例如 +2+2+2 是 0000…0010，反轉得 1111…1101，加 1 得 1111…1110，就是 −2-2−2。

page-22 Sign Extension#

把一個 nnn-bit 的數放進更寬的空間時（例如把 8-bit 的數放進 64-bit 的 register），數值必須保持不變：

Definition (Sign extension（符號擴充）)

Two’s complement 的數變寬時，把 sign bit 複製到新增的每一個 bit。Unsigned 的數則是補 0，叫 zero extension。

8 bits 擴成 16 bits 的例子：+2+2+2 是 0000 0010 → 0000 0000 0000 0010；−2-2−2 是 1111 1110 → 1111 1111 1111 1110。 為什麼複製 sign bit 不會改變數值？在 two’s complement 裡，正數左邊補再多個 0、負數左邊補再多個 1，代表的值都不變——例如 8-bit 的 1111 1110 與 16-bit 的 1111 1111 1111 1110 都是 −2-2−2。Sign extension 就是照這個規則把新增的 bits 填滿。

RISC-V 最常用到 sign extension 的地方，是把一個 byte load 進 64-bit 的 register：lb（load byte）做 sign extension，lbu（load byte unsigned）做 zero extension。 C 的字元通常當成 unsigned 處理，所以實務上幾乎都用 lbu。

page-23–26 Representing Instructions（§2.5）#

資料怎麼用 bits 表示講完了，接下來是 instruction 本身：instruction 也得用 0 與 1 存在 memory 裡。

Definition (Machine code)

Instruction 的二進位表示叫 machine language，一連串這樣的 instruction 叫 machine code。

RISC-V 的 instruction 一律 32 bits（一個 word），而且只用少數幾種 instruction format—— 也就是規定一條 instruction 分成哪幾個 field（欄位）、每個 field 佔幾 bits。固定長度加上少數幾種格式，又是 Design Principle 1 的 regularity。

page-27–28 I-format and S-format#

R-format 的 rs1、rs2、rd 都是 register 編號，放不下常數。但 load 需要兩個 register 加一個常數 offset，如果把 offset 塞進 5-bit 的 field，offset 最大只有 31，太小了。 RISC-V 的設計者面前有兩條路：讓 load 這類需要常數的 instruction 變長，或是另外設計一種 format。這個取捨就是第三條設計原則：

Design Principle 3：Good design demands good compromises

RISC-V 的折衷是：所有 instruction 維持 32 bits，但為不同種類的 instruction 準備不同 format。 多種 format 會讓硬體解碼（decoding，從一條 instruction 的 bits 判斷要做什麼運算、用哪些 register）麻煩一點，所以各 format 盡量長得相似。

page-42–43 Procedure Calling（§2.8）#

Definition (Procedure)

一段寫好、可以被重複呼叫的程式，透過 argument 接收輸入、回傳結果，也就是 C 的 function。 呼叫別人的一方叫 caller，被呼叫的一方叫 callee。

要分清楚 procedure 和 procedure call：procedure 是寫好的那段 code，只有一份；procedure call 是它被執行的「一次」。 同一個 procedure 可以被呼叫很多次，甚至自己呼叫自己（page-49 的遞迴 fact）：fact(2) 呼叫 fact(1)、fact(1) 再呼叫 fact(0)，是 1 個 procedure、3 次 call。

Procedure 是軟體做 abstraction 的方式：寫程式的人一次只要專心處理一小塊，而且同一段程式可以在很多地方重複使用。 執行一次 procedure call 要經過六個步驟：

  1. Caller 把 argument 放在 callee 拿得到的地方——RISC-V 約定放在 x10 到 x17；
  2. Caller 把控制權交給 callee，也就是跳到 callee 的第一條 instruction；
  3. Callee 取得它需要的儲存空間，例如在 stack 上空出位置（page-44）；
  4. Callee 執行 procedure 的工作；
  5. Callee 把結果放在 caller 拿得到的地方（x10、x11）；
  6. Callee 跳回 caller 呼叫它的那個位置。因為同一個 procedure 可能從很多地方被呼叫，callee 得知道要回到哪裡——這個 address 記在 x1。

用哪些 register 傳 argument、回傳值、return address，硬體並不在乎；這是軟體之間的約定，叫 calling convention， 寫在 RISC-V 官方的 ABI 文件裡，屬於 ch01 說的 ABI 的一部分。 需要約定，是因為 caller 和 callee 常常不是同一個人寫、也不是同時編譯的（例如你的程式呼叫早就編譯好的 C library）， 雙方事先講好「argument 放 x10–x17、結果放 x10」，才接得起來。assembler 也因此替 x10–x17 取了別名 a0–a7。

步驟 2（跳去 callee）與步驟 6（跳回 caller）各需要一條專用的 instruction。說明它們之前，先定義一個 register：

Definition (Program counter（PC）)

存放「目前正在執行的 instruction 的 address」的 register。（注意：這裡的 PC 跟 ch01 的 personal computer 無關。）

jal 做兩件事：

  1. 把下一條 instruction 的 address（PC + 4，因為每條 instruction 4 bytes）存進 x1。這個 address 叫 return address，是 callee 做完後要回來的地方；

jalr 跟 jal 一樣做「存下一條的 address、然後跳」兩件事，差別在跳去哪裡：

  • jal 跳到寫在 instruction 裡的 label；
  • jalr 跳到「register 的值 + offset」，這裡是 x1 + 0，也就是剛才 jal 存下的 return address。

Callee 返回時一定要用 jalr，因為要回去的地方取決於是誰呼叫它，寫 callee 的 code 時並不知道，只能從 x1 讀出來。 例如在 address 1000 執行 jal x1, f，x1 變成 1004；f 最後的 jalr x0, 0(x1) 就跳回 1004。若改由 address 2000 呼叫 f，同一條 jalr 就跳回 2004。

至於 rd 寫 x0：jalr 也會把 PC + 4 寫進 rd，但返回時不需要再記一個 return address，而 x0 不能被改，寫進去的值會被丟掉，等於不存。

jalr 還有一個用途是 computed jump：例如 C 的 switch，compiler 可以把各個 case 的 address 做成一張表（branch table），用 ld 讀出要去的 address，再用 jalr 跳過去。 同理，jal x0, Label 不存 return address，就是單純跳到 Label 的無條件跳躍。

page-44–47 Leaf Procedures and the Stack#

Callee 執行時也需要 register，但 caller 可能正把自己還要用的值放在某些 register 裡，callee 不能把這些值改掉。 解法是 callee 先把要用的 register 舊值存到 memory，用完再還原。這些舊值要存在 memory 的哪裡？存在 stack：

Definition (Stack 與 stack pointer)

Stack（堆疊）是 memory 中一塊後進先出（last-in-first-out）的區域，用來存放 procedure 要保存的 register 與區域資料。 Stack pointer（sp，就是 x2）指向 stack 目前的頂端。放資料進 stack 叫 push，取出叫 pop。 依照慣例，stack 從高 address 往低 address 長：push 時把 sp 減小，pop 時把 sp 加大。 每條 thread 有自己的一個 stack；程式只有一條 thread 時，就只有一個 stack。

同一條 thread 裡的所有 procedure call 都共用這一個 stack，但不會互相干擾：每次 call 開始時把 sp 往下移，開出一段只屬於這次 call 的空間，返回時再把 sp 移回去釋放。 這一段叫這次 call 的 frame（page-52 會詳細看）。Procedure call 本身就是後進先出——最後被呼叫的一定最先返回——所以剛好可以用 stack 來管理。

page-48–50 Non-Leaf Procedures#

會再呼叫其他 procedure 的 procedure 叫 non-leaf procedure。Non-leaf procedure 會遇到 leaf procedure 沒有的問題： 假設 main 用 jal x1, A 呼叫 A、argument 放在 x10；A 又用 jal x1, B 呼叫 B、argument 也放在 x10。 A 呼叫 B 的那條 jal 會把 x1 蓋成「B 返回 A 的位置」，A 原本要返回 main 的 address 就不見了，A 回不去 main；A 收到的 argument（x10）也被 B 的 argument 蓋掉。

  • Caller 負責存：呼叫之後還要用的 argument register（x10–x17）與 temporary register；
  • Callee 負責存：return address x1（如果它會再呼叫別人），以及它用到的 saved register。

page-52 Local Data on the Stack#

除了保存 register，stack 也放 procedure 裡塞不進 register 的區域變數，例如 local array 或 structure（C 的 automatic variable，procedure 結束就消失的變數）。 這些區域變數由 callee 在自己的 stack 空間裡配置。

問題：多個 thread 同時改同一個變數。 ch01 說 multicore 之後，程式要靠多條 thread 平行執行才能變快。 同一個 process 的 thread 共用同一份 memory，所以它們常要讀寫同一個變數。假設兩條 thread 都執行 count = count + 1， count 原本是 0。這一行 C 在 RISC-V 是三條 instruction：ld 讀出 count、addi 加 1、sd 寫回。如果兩條 thread 的 instruction 交錯成這樣：

順序Thread 1Thread 2memory 裡的 count
1ld：讀到 00
2ld：讀到 00

4addi，sd：寫入 11

兩條 thread 各加了一次，count 卻只變成 1，因為 thread 2 讀的是 thread 1 還沒寫回之前的舊值。

Definition (Data race（資料競爭）)

兩條不同 thread 對同一個 memory 位置的存取，至少一個是寫入，而且兩者之間沒有同步（沒有規定誰先誰後）。 這時程式的結果取決於 instruction 剛好怎麼交錯，每次執行都可能不同。

解法：lock。 把「讀寫共享變數的那段程式」設成同一時間只能有一條 thread 執行，這段程式叫 critical section（臨界區段）， 這種限制叫 mutual exclusion（互斥）。做法是在 memory 放一個 lock 變數：0 表示沒有 thread 在 critical section 裡，1 表示有。 Thread 要進入 critical section 前先把 lock 從 0 改成 1（上鎖），出來後再改回 0（解鎖）；看到 lock 是 1 就等。

為什麼上鎖需要硬體幫忙。 用一般的 instruction 上鎖，得先 ld 讀出 lock，看到是 0 再 sd 寫入 1。 但兩條 thread 可能都先執行了 ld、都讀到 0，然後都寫入 1、都以為自己拿到了 lock——跟上面 count 的問題一模一樣。 問題出在「讀」和「寫」之間可以被別的 thread 插進來，所以需要：

Definition (Atomic read-modify-write)

對一個 memory 位置「讀出、再寫入」，而且保證讀和寫之間沒有任何其他存取能插進來，整個動作像不可分割的一步。

硬體提供這個能力有兩種做法：一是單一 instruction 同時讀和寫，例如 atomic swap（把一個 register 和一個 memory 位置的值互換）； 二是用一對 instruction，由硬體檢查兩者之間有沒有別人插進來。單一 instruction 得在一條 instruction 裡完成一次 memory 讀加一次 memory 寫，processor 比較難做，所以 RISC-V 選第二種（page-63）：

  • lr.d rd, (rs1)（load reserved）：從 rs1 指的 address 讀一個 doubleword 到 rd，同時硬體記住這個 address，叫 reservation。之後只要有其他存取寫了這個 address，reservation 就失效。
  • sc.d rd, rs2, (rs1)（store conditional）：如果 reservation 還有效，就把 rs2 寫進 rs1 指的 address，並在 rd 寫 0 表示成功； 如果 reservation 已經失效，就不寫，在 rd 寫非 0 表示失敗。

失敗時程式回頭重做 lr.d 與 sc.d，直到成功為止。成功的那一次，保證 lr.d 讀到之後、sc.d 寫入之前，沒有別人改過這個位置， 所以「lr.d 讀、sc.d 寫」這一對的效果就跟 atomic read-modify-write 一樣。

Static linking 的兩個缺點。 一是 library 的 code 被複製進 executable，之後 library 修了 bug，已經 link 好的程式也不會跟著更新。 二是 executable 裡任何一處呼叫到的 library routine 都會被整個包進來，即使這次執行根本不會走到那些呼叫，executable 因此變得很大 （課本說 RISC-V Linux 上的標準 C library 就有 1.5 MiB）。

Definition (Dynamically linked library（DLL，動態連結函式庫）)

在程式執行時才連結、載入的 library routine。Executable 裡只記「要用哪個 library 的哪個 routine」，不包含 routine 本身。 好處是程式自動用到最新版的 library，executable 也很小。代價是 library 的 code 必須能放在任何 address 執行。

Lazy linkage（page-70）：用到才連結。 最早的 DLL 在程式啟動時就把所有可能用到的 routine 都連結好；lazy linkage 則等到某個 routine 第一次被呼叫才連結。 做法是在「呼叫」與「routine」之間多一層間接：data segment 裡有一張表，每個 library routine 佔一格，格子裡放一個 address； 程式呼叫 routine 時，先跳到一小段固定的轉接 code（叫 stub），stub 用 ld 從表裡讀出 address，再用 jalr 跳過去。

  • 第一次呼叫（圖 a）：表裡的 address 一開始指向一段準備好的 code，它把「要哪個 routine」的編號放進 register，然後跳到 dynamic linker/loader。 Dynamic linker/loader 找到這個 routine、把它載入 memory，把表裡那格改成 routine 的真正 address，再跳到 routine 執行。
  • 之後的呼叫（圖 b）：表裡已經是 routine 的 address，stub 的 ld、jalr 直接跳到 routine。

所以只有第一次呼叫要付找 routine、載入的代價，之後每次只多一次經過表的間接跳躍；從 routine 返回則完全沒有額外代價。

Java（page-71）：另一種翻譯方式。 Java 的目標是同一份程式能安全地跑在任何電腦上，即使慢一點也可以。所以 Java compiler 不把程式編成某個 ISA 的 machine code：

  • Java compiler 先把程式編成 Java bytecode：一種為了方便 interpret 而設計的簡單 instruction set，不屬於任何一台真實的電腦；
  • 執行時，由 Java Virtual Machine（JVM） 負責。JVM 是一個 interpreter（用軟體讀一條 instruction、模擬它的效果、再讀下一條的程式），在任何電腦上都能執行 bytecode；
  • Interpret 很慢，所以 JVM 會找出被執行最多次的 method（Java 的 procedure），交給 Just In Time（JIT）compiler 在執行期間編成這台電腦的 machine code，之後就直接執行 machine code。

Interpret 換到了可攜性，代價是 performance；JIT 則把大部分 performance 拿回來（數字在 page-79）。

page-81–83 Arrays versus Pointers（§2.14）#

C 初學者常卡在 pointer。把「用 array index」和「用 pointer」兩種寫法翻成 assembly 對照，就能看清楚 pointer 其實就是一個 address。 兩個 procedure 都把一個 array 清成 0（array 的 base address 在 x10、元素個數 size 在 x11）：

C 的 p = p + 1 表示 p 指向下一個元素；元素是 8 bytes 的 long long int，所以 p 存的 address 實際加 8。

clear1 的 loop 每圈 5 條 instruction：i 每加 1，就得在 loop 裡重新算一次 address（乘 8 再加 base）。 clear2 的 loop 每圈只要 3 條：p 本身就是 address，每圈直接加 8；算終點 address 的乘法與加法只在 loop 前做一次。 （比較 address 用 unsigned 的 bltu，因為 address 沒有負數。）

clear2 用的兩個技巧在 compiler 裡都有名字：

  • Strength reduction：用比較便宜的運算取代昂貴的運算，例如用 shift 或每圈累加 8，取代乘法；
  • Induction variable elimination：不再每圈用 i 重算 address，改成讓 address 本身每圈遞增，i 這個變數因此可以消掉。

現代 compiler 對 clear1 也會自動做這兩件事，產生跟 clear2 一樣好的 code。所以結論是：寫清楚、安全的程式（例如用 array），最佳化交給 compiler。

page-84–85 Real Stuff: MIPS Instructions（§2.16）#

MIPS 是 RISC-V 在商業上的前輩，學會 RISC-V 就幾乎會 MIPS。兩者的共同點：

  • 所有 instruction 都是 32 bits；
  • 32 個 general-purpose register，0 號固定為 0；另有 32 個 floating-point register；
  • 只有 load、store 能存取 memory；
  • byte、halfword、word、doubleword 的 load/store 都用同一套 addressing mode。

主要差別在比大小的 branch。 RISC-V 直接提供 blt、bge、bltu、bgeu。MIPS 只有 beq、bne，比大小要分兩步： 先用 slt（set less than）把比較結果寫成 0 或 1 存進一個 register，再用 beq、bne 判斷那個 register。例如「a < b 就跳到 L」，a、b 在 RISC-V 放在 x8、x9，在 MIPS 放在 s0、s0、s0、s1：

MIPS 的做法讓硬體簡單一點，但同樣的程式需要更多 instruction。

Instruction format（page-85）。 兩者的 register field 都是 5 bits（因為都有 32 個 register），只是位置不同； MIPS 的 opcode 是 6 bits、放在最左邊，常數 field 是 16 bits，比 RISC-V 的 12 bits 長。

page-86–92 Real Stuff: x86 Instructions（§2.17）#

x86 走的是另一條路：提供功能更強、更複雜的 instruction，希望同樣的程式需要的 IC 更少。這類 ISA 叫：

Definition (CISC（complex instruction set computer）)

Instruction 數量多、單條功能強、長度不固定的 ISA，例如 x86。相對地，RISC-V、MIPS 這類刻意保持 instruction 簡單、規律的 ISA 叫 RISC（reduced instruction set computer）。

風險在於：instruction 變複雜，每條 instruction 也可能變慢（clock cycle 變長，或每條需要更多 cycle），把 IC 減少的好處吃掉——這正是 ch01 的 CPU time = IC × CPI × clock cycle time。

一路加上去的歷史（page-86–88）。 x86 不是一群人一次設計好的，而是近 40 年間不斷往上加東西。 每一步都維持 backward compatibility（新的 processor 仍能執行舊程式的 machine code），所以舊的 instruction 一條都不能拿掉：

Register 與 operand（page-89–90）。 80386 只有 8 個 general-purpose register（EAX、ECX、EDX、EBX、ESP、EBP、ESI、EDI）， 另有 EIP（x86 的 PC）、EFLAGS（記錄運算結果狀態的 register，branch 靠它判斷）與幾個 segment register。RISC-V 的 32 個 register 是它的 4 倍。

x86 的算術 instruction 只有兩個 operand，其中一個同時是 source 和 destination：add eax, ebx 的意思是 eax = eax + ebx，eax 原本的值會被蓋掉。 而且其中一個 operand 可以直接在 memory，例如 add eax, [ebx+8]（把 memory 裡 ebx + 8 位置的值加到 eax）；只是不能兩個 operand 都在 memory：

編碼（page-91）。 x86 的 instruction 長度從 1 到 15 bytes 不等：opcode 後面可能接一個描述 addressing mode 的 byte（postbyte）， 前面還能加 prefix byte 改變這條 instruction 的行為，例如改變 operand 長度、重複執行、在同步時鎖住 memory。 跟 RISC-V 固定 32 bits 相比，光是判斷一條 instruction 有多長、各部分在哪裡，就得先讀過好幾個 byte。

怎麼實作（page-92）。 這麼複雜的 instruction set 很難直接做成快的硬體。現代 x86 processor 的做法是在硬體裡先把每條 instruction 翻成較簡單的 micro-operation： 簡單的 instruction 翻成 1 個，複雜的翻成好幾個，而真正執行 micro-operation 的核心其實很像 RISC。 這個翻譯的成本很高，但 x86 的市場夠大，撐得起這筆投資，performance 也能跟 RISC 相當。Compiler 則會避開那些難以做快的複雜 instruction。

page-93–94 The Rest of the RISC-V Instruction Set（§2.18）#

RISC-V 把 instruction set 分成一個 base（叫 I，integer）加上幾個 extension，不同用途的電腦只要實作需要的部分。 這一章已經講完 base 的大部分，剩下的有（page-93）：

  • auipc rd, immed：rd = PC + (immed << 12)。跟 lui 一樣放 20-bit 常數到高位，但加的是 PC。 配上 jalr 可以跳到 PC 附近 ±2 GiB 內的任何位置，也能寫出不管被載入到哪個 address 都能正確執行的 code（DLL 需要這種 code）。
  • slt、sltu、slti、sltiu：set less than，跟 MIPS 一樣把比較結果寫成 0 或 1。
  • addw、subw、addiw、sllw、srlw、sraw、slliw、srliw、sraiw：只對低 32 bits 運算，結果 sign-extend 成 64 bits。 因為 C 與 Java 的 int 仍然是 32 bits，64-bit 的電腦上也常做 32-bit 的運算。

Base 本身也有兩個版本：本章用的 64-bit 的 RV64I，以及 register 只有 32 bits、給低成本 processor 用的 RV32I。

page-95–97 Fallacies and Pitfalls#

Fallacy：更強大的 instruction 帶來更高的 performance

強大的 instruction 確實讓 IC 變少，但它難以實作，可能連帶拖慢所有 instruction（包括簡單的那些）；而 compiler 很擅長用簡單的 instruction 組出快的 code。 課本的例子：x86 可以在 move instruction 前加一個「重複執行」的 prefix，一條 instruction 就搬完一大塊 memory，看起來最省事。 但改用一般的 load、store 一個一個搬，速度是它的 1.5 倍；再改用較寬的 floating-point register 搬，是它的 2 倍。

Fallacy：要最高 performance 就得寫 assembly

現代 compiler 比人更懂現代 processor 的細節（第 4 章的 pipeline、第 5 章的 memory hierarchy），手寫很難贏過它。 而且 assembly 的行數多得多，寫得慢、bug 多、難維護，也只能在一種 ISA 上執行。

Fallacy：為了 binary compatibility，成功的 instruction set 不會再變

為了 backward compatibility，舊的 instruction 確實不能拿掉或改變，但新的 instruction 會一直加進來。 page-96 的圖：x86 的 instruction 數從 1978 年不到 100 條，長到 2016 年左右約 1400 條，平均每個月多一條以上。

Pitfall：以為相鄰的 word 在相鄰的 address

Memory 是 byte addressed（page-12），下一個 word 的 address 要加 4、下一個 doubleword 要加 8，不是加 1。

Pitfall：procedure 返回後還在用指向它區域變數的 pointer

區域變數放在這次 call 的 frame 裡（page-52），procedure 一返回，frame 就被釋放，那塊 stack 很快會被下一次 call 拿去用。例如：

page-98 Concluding Remarks（§2.23）#

整章看下來，RISC-V 的長相幾乎都能用三條設計原則解釋：

  1. Simplicity favors regularity：instruction 一律 32 bits、算術 instruction 一律三個 register operand、rs1、rs2、rd 在每個 format 都在同一位置。
  2. Smaller is faster：只有 32 個 register。
  3. Good design demands good compromises：在「要放得下大常數與遠的 address」和「所有 instruction 一樣長」之間折衷，才有多種 format、lui 與 PC-relative addressing。

再加上 ch01 的 make the common case fast：常數常用，所以有 immediate；branch 多半跳得近，所以用 PC-relative addressing。

軟硬體也一路分層：compiler 把 C 翻成 assembly，assembler 再翻成 machine code，還用 pseudoinstruction 讓 assembly 有比硬體更多的寫法； linker、loader 再把 machine code 接起來、放進 memory 執行——每一層都把細節藏在下一層，這又是 abstraction。 RISC-V 是 RISC 這類 ISA 的典型，拿它對照 x86，就能看到兩種設計哲學的差別。
