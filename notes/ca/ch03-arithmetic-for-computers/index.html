Overflow 什麼時候會發生#

64-bit 的數相加，正確結果可能需要 65 bits，多出來的那一位放不下，這就是 overflow。關鍵觀察是：

  • 兩個不同正負號的數相加，不會 overflow。 結果的絕對值不會超過兩個 operand 中較大的那個，例如 −10+4=−6-10 + 4 = -6−10+4=−6。既然 operand 放得下，結果也放得下。
  • 兩個相同正負號的數相減，不會 overflow。 因為 c−a=c+(−a)c - a = c + (-a)c−a=c+(−a)，相同正負號的減法等於不同正負號的加法。

所以 overflow 只會出現在剩下的情況，而且判斷方法很簡單——看結果的 sign bit 對不對：

運算AB結果顯示 overflow

A + B< 0< 0≥ 0（sign bit 是 0）
A − B≥ 0< 0< 0
A − B< 0≥ 0≥ 0

為什麼看 sign bit 就夠？正確結果只比 64 bits 多一位，所以真正被擠掉的只有「正確的 sign」，原本的 sign bit 位置被結果的數值位佔走了，才會出現「兩個正數加起來變負數」這種荒謬的結果。

Unsigned 的 overflow 更好判斷：加法的結果比任一個加數小，或減法的結果比被減數大，就是 overflow。 Unsigned 最常見的用途是 memory address，而 address 運算通常直接忽略 overflow。

圖像與聲音的資料通常很窄：像素的每個顏色 8 bits，聲音的 sample 16 bits。而且同一個運算會套用在一大串這樣的資料上。所以處理器做了兩件事：

1. 切開 carry chain，一次做很多個小加法。 一個 64-bit adder 裡，進位是一路從 bit 0 傳到 bit 63。 如果在每 8 bits 的邊界把進位切斷，同一個 adder 就變成 8 個互不影響的 8-bit adder；切在 16 或 32 bits 的邊界，就是 4 個 16-bit 或 2 個 32-bit adder。 一條 instruction 同時處理多筆資料，這叫：

2. Saturating（飽和）運算。 Two’s complement 的加法 overflow 時會繞回來（modulo 2n2^n2n）：最大的正數再加 1 變成最負的數。 對多媒體資料這很糟：把音量一直調大，聲音突然變得最小聲。Saturating 運算在 overflow 時改成給出能表示的最大值（或最小值）， 就像音量旋鈕轉到底就停在最大聲。聲音的 clipping、影像的 saturation 都是這個行為。

優化後的硬體（page-08）#

第一版能用，但很浪費：128-bit 的 Multiplicand register、128-bit 的 ALU，而且每個 bit 要花三個 cycle。 優化版只用 64-bit 的 Multiplicand register、64-bit 的 ALU，加上一個 129-bit 的 Product register，每個 bit 一個 cycle。它是從三個觀察一步步推出來的。

觀察 1：每一輪，ALU 真正有用的只有 64 bits。 回頭看上面的表。第 1 輪做完，Product 的最低位（bit 0）就再也不會變了： 之後加進來的 Multiplicand 都已經至少左移 1 位，最低位一定是 0，碰不到 bit 0。第 2 輪做完，bit 1 也固定了，依此類推。 反過來，第 iii 輪的 Multiplicand 只佔 bit iii 到 bit i+63i+63i+63，更高的位都是 0。 所以每一輪的加法只會改到一個 64 bits 寬的「窗口」，窗口右邊是已經算完的位，左邊還沒用到。128-bit 的 ALU 有一半在做白工。

觀察 2：窗口不動、改成 Product 動。 第一版是 Multiplicand 每輪往左移、去對準窗口； 反過來讓 Product 每輪往右移 1 bit，兩者的相對位置完全一樣，但窗口就永遠固定在 Product 的左半。於是：

  • Multiplicand 不用再移，register 只要 64 bits；
  • 加法永遠是「Product 左半 + Multiplicand」，ALU 只要 64 bits；
  • 已經算完的低位，隨著右移一位一位進入 Product 的右半。

觀察 3：Product 的右半跟 Multiplier 可以共用。 一開始 Product 右半是空的（還沒有任何算完的位），之後每輪右移進來一個算完的位； 而 Multiplier 每輪用掉最右邊一位、右移一次，剛好空出一個位置。一個一位一位填進來，一個一位一位用掉，總長永遠是 64 bits。 所以不需要獨立的 Multiplier register：一開始就把 multiplier 放進 Product 的右半。每輪要檢查的 multiplier 位，就是整個 Product register 的最右邊一位（Product0）。

合起來，演算法變成（重複 64 次）：

  1. 看 Product0：是 1 就把 Multiplicand 加到 Product 的左半，是 0 就不加；
  2. 整個 Product register 右移 1 bit。

Product register 多一個 bit（共 129 bits），是因為左半加 Multiplicand 可能產生 carry out；這個 carry 在右移時會移進左半的最高位，不能丟掉。

為什麼一個 cycle 就夠？ 檢查 Product0、做加法、右移不再是三個 register 各自的動作：加法的結果直接「錯開一位」寫回 Product register，就同時完成了加和移。

沒有改變的是：還是一個 bit 一輪。 64-bit 乘法要 64 輪，時間跟 bit 數成正比。 投影片說這樣就夠了：只要程式裡乘法不常見（加減法通常是乘法的 5 到 100 倍），乘法慢一點影響不大。 但 ch01 的 Amdahl’s Law 提醒我們，就算頻率不高，太慢的運算還是可能拖住整體 performance。要真正跳一級，得用下面 page-09 的做法。

Signed 乘法。 最簡單的做法是：先把兩個數轉成正數相乘，記住原本的正負號，正負號不同時再把乘積取負號。 另一種做法是直接用上面的演算法，只要右移時做 sign extension（ch02）就行了。

前兩版都是一輪加一次，第 iii 輪要等第 i−1i-1i−1 輪加完，64 次加法排成一條線。但這 64 個要加的數其實一開始就全部知道：

Definition (Partial product（部分積）)

Multiplier 第 iii 位乘上 multiplicand、再左移 iii 位：該位是 1 就是 multiplicand 左移 iii 位，是 0 就是 0。乘積是所有 partial product 的總和。

產生它們不需要加法：multiplicand 的每一位跟 multiplier 第 iii 位做 AND 即可。左移也不需要電路，只要把第 jjj 位的線接到 adder 的第 i+ji+ji+j 號輸入、最低 iii 個輸入接 0——位移量 iii 是固定的，做晶片時就接好了（不像 sll x5, x6, x7 的位移量要執行時才知道）。 所以 64 個 partial product 能同時產生，問題只剩怎麼最快把它們加起來。

  • Unsigned：mulhu 的結果是 0，就沒有 overflow；
  • Signed：mulh 的結果每一位都等於 mul 結果的 sign bit（也就是高半部分只是 sign extension），就沒有 overflow。

  1. Remainder = Remainder − Divisor；

優化後的硬體（page-13）#

跟乘法一樣的改良：Divisor 固定不動、改成 Remainder 往左移；Divisor register 與 ALU 減成 64 bits； Quotient 不再獨立，而是從 Remainder register 的右半移進去（Remainder 每左移一次，右邊空出一位，剛好放新的商位）。Remainder register 同樣是 129 bits。每個商位一個 cycle。

更快的除法（page-14）#

乘法可以用一棵 adder 樹一次算完，除法不行：每一步要不要減，取決於上一步餘數的正負號，步驟之間有先後依賴，沒辦法同時做。

能做的是讓每一步產生不只一個商位。SRT division 用 divisor 與餘數的最高幾個 bits 去查表，猜接下來幾個商位，猜錯了在後面的步驟修正；現在典型是一步 4 bits。但還是得一步一步來。 （page-49 的 Pentium FDIV bug 就是這張表出了錯。）

Nonrestoring division

Restoring division 在餘數變負時要多花一次加法把 divisor 加回來。其實可以不加回來： 設減完的餘數是 r−d<0r - d < 0r−d<0，下一步本來要「加回 ddd、左移、再減 ddd」，也就是 (r−d+d)×2−d=2r−d(r - d + d) \times 2 - d = 2r - d(r−d+d)×2−d=2r−d； 直接把負的餘數左移再加 ddd，得到 (r−d)×2+d=2r−d(r - d) \times 2 + d = 2r - d(r−d)×2+d=2r−d，結果一樣。這樣每一步只做一次加或減，叫 nonrestoring division。

投影片的 C code

投影片（和課本）寫成 double c[][]，這在 C 裡不合法：多維陣列參數除了第一維，其他維的大小都要寫出來，compiler 才知道一列有多長。上面已改成 c[][32]。

c、a、b 的 address 在 x10、x11、x12，i、j、k 放 x5、x6、x7。

怎麼算 c[i][j] 的 address。 C 的二維陣列是 row-major：一列一列接著存，所以 c[i][j] 前面有 i 整列（每列 32 個元素）再加 j 個元素：

address of c[i][j]=c+(i×32+j)×8\text{address of } c[i][j] = c + (i \times 32 + j) \times 8address of c[i][j]=c+(i×32+j)×8

32 和 8 都是 2 的次方，乘法可以換成左移（slli 5 和 3）。

一個優化：c[i][j] 放在 register 裡。 最內層 loop 的 index 是 k，c[i][j] 在整個 k loop 裡都不變。 所以只要在 k loop 開始前 load 一次到 f0，在 f0 裡累加，loop 結束後再 store 回去，不必每次都讀寫 memory。

i、j、k 是 size_t（unsigned），所以用 unsigned 的 bltu 比較。注意最內層 loop（L3 到 bltu x7）有 14 條 instruction，真正做浮點運算的只有 fmul.d 和 fadd.d 兩條，其他都在算 address——page-44 會看到怎麼改善。

Row-major 與 column-major

C 用 row-major；Fortran 則用 column-major，一行一行存。page-44 的 DGEMM 就是用 column-major 的寫法。

page-39 Accurate Arithmetic#

整數在範圍內的每個值都能精確表示，floating point 不行：1 到 2 之間有無限多個實數，double 卻只能精確表示其中 2522^{52}252 個。 所以 floating point 的結果通常是近似值，而 rounding（捨入）決定選哪一個近似值。

Guard 與 round bits。 要 rounding 得準確，運算過程中得比最後的結果多算幾位。IEEE 754 在中間計算時多保留兩個 bit：

Definition (Guard bit、round bit、sticky bit)
  • Guard 與 round：中間計算時，在最右邊多保留的第一、第二個 bit；
  • Sticky：round bit 右邊只要還有任何非 0 的 bit 被移出去，sticky bit 就是 1。它記住「還有沒有剩下的東西」。

課本的例子：2.56×100+2.34×1022.56 \times 10^0 + 2.34 \times 10^22.56×100+2.34×102，只能留 3 位有效數字。對齊後 2.56×100=0.0256×1022.56 \times 10^0 = 0.0256 \times 10^22.56×100=0.0256×102：

  • 有 guard 與 round：多留的兩位存住 5 與 6，2.34+0.0256=2.36562.34 + 0.0256 = 2.36562.34+0.0256=2.3656，四捨五入成 2.37×1022.37 \times 10^22.37×102；
  • 沒有：0.0256 只剩 0.02，2.34+0.02=2.36×1022.34 + 0.02 = 2.36 \times 10^22.34+0.02=2.36×102，最後一位差了 1。

Sticky 的用途。 改算 5.01×10−1+2.34×1025.01 \times 10^{-1} + 2.34 \times 10^25.01×10−1+2.34×102：對齊後是 0.00501×1020.00501 \times 10^20.00501×102，guard 與 round 只留得住 0.00500.00500.0050，和是 2.34502.34502.3450——看起來剛好在 2.34 與 2.35 的正中間。 但實際上被移出去的還有一個 1，真正的值比中間大一點，應該進位成 2.35。Sticky bit 記下了「還有 1 被移出去」，所以能正確判斷。

精確度怎麼衡量。

Definition (ulp（units in the last place）)

Significand 最後一位的單位。誤差通常用「差了幾個 ulp」表示。

IEEE 754 保證（沒有 overflow、underflow 或 invalid operation 時）結果與真正的值相差在 0.5 ulp 以內，也就是選到最接近的那個可表示的數。

Rounding modes。 IEEE 754 提供四種：

Mode做法
Round toward +∞+\infty+∞一律往上
Round toward −∞-\infty−∞一律往下
Truncate往 0 截斷
Round to nearest even取最近的；剛好在正中間時，取最後一位是偶數的那個

最後一種是預設值。為什麼正中間時要取偶數，而不是一律進位？一律進位的話，所有「剛好一半」的情況都往同一邊偏，誤差會累積； 取偶數則大約一半進位、一半捨去，平均起來不偏。

投影片的重點：這些額外的 bit 與 rounding mode 讓程式設計師能細調數值行為，但不是每個 FP 硬體都實作全部選項，大部分語言和函式庫也只用預設值。要做到多完整，是硬體複雜度、performance 與市場需求之間的取捨。

Fused multiply-add

RISC-V 等 ISA 有一條 instruction 同時做乘與加：a=a+b×ca = a + b \times ca=a+b×c。除了少一條 instruction，它只在最後 rounding 一次（分開做的話，乘完 round 一次、加完再 round 一次），所以更精確。這種 instruction 叫 fused multiply-add（FMA），已加入 IEEE 754-2008。page-45 的 _mm512_fmadd_pd 就是 FMA。

page-40 Subword Parallelism（§3.6）#

回到 page-05 的想法。圖像與聲音程式常對一串短資料做同樣的運算，所以把一個寬的 adder 切開 carry chain，一次做很多個窄的加法。例如一個 128-bit adder 可以做：

  • 16 個 8-bit 加法；
  • 8 個 16-bit 加法；
  • 4 個 32-bit 加法；
  • 2 個 64-bit 加法。

切開 carry chain 的成本很低，速度卻可能快好幾倍。

Definition (Subword parallelism)

在一個寬的 word 裡同時對好幾個較窄的資料做運算。也叫 data-level parallelism、vector parallelism，或 SIMD（Single Instruction, Multiple Data）。

（課本寫作時 RISC-V 還沒有這類 instruction；後來 RISC-V 加入了 V（vector）extension。下一節看 x86 的實例。）

page-41–43 x86 FP Architecture（§3.7）#

x87：stack 架構（page-41）。 x86 的浮點運算最早來自 8087 FP coprocessor（1980 年，獨立於 CPU 的另一顆晶片）：

  • 8 個 80-bit 的 extended-precision register；
  • 這 8 個 register 當成 stack 用：instruction 用相對於 stack 頂端（TOS，top of stack）的位置稱呼它們，ST(0) 是頂端、ST(1) 是下一個……；
  • Memory 裡的資料是 32-bit 或 64-bit 的浮點數，也可以是整數，load 時轉成 80-bit，store 時轉回去。

Stack 架構讓 compiler 很難產生好的 code：每個運算都得先把 operand 推到 stack 頂端，register 不能隨意指定，結果 FP performance 很差。

投影片的筆誤

投影片寫 F2XMI、FPSIN，應該是 F2XM1（2 的 x 次方減 1）與 FSIN。

SSE2（page-43）。 2001 年 Intel 加入 SSE2（Streaming SIMD Extension 2），改用一般的 register 而不是 stack：

  • 128-bit 的 register（XMM），32-bit 模式有 8 個，AMD64／Intel 的 64-bit 模式（EM64T）擴充到 16 個；
  • 一個 register 可以放 2 個 64-bit double，或 4 個 32-bit single；
  • 一條 instruction 同時對裡面的每個 operand 運算，也就是 SIMD。
投影片的筆誤

投影片寫 “Adds 4 × 128-bit registers, extended to 8”，實際是 8 個、64-bit 模式擴充到 16 個；“4 × 32-bit double precision” 應該是 4 個 32-bit single precision。

之後 x86 繼續加寬：2011 年的 AVX（Advanced Vector Extensions）有 256-bit 的 YMM register（4 個 double），AVX-512 再加寬到 512-bit 的 ZMM register（8 個 double）。 AVX 的 instruction 名字前面多一個 v，而且是三個 operand（例如 vaddpd %ymm0, %ymm1, %ymm4），比 SSE2 的兩個 operand 少用一些 register 和 instruction。

page-44–46 Matrix Multiply（§3.8）#

這一節用 page-36 的 DGEMM 示範 subword parallelism 能快多少。

未優化的版本（page-44）：

矩陣大小 n 是參數，所以改用一維陣列自己算 index。X[i + j*n] 代表 X[i][j]：這是 column-major 的排法，同一個 column 的元素在 memory 裡相鄰（X[i][j] 與 X[i+1][j] 差一格）。

用 AVX-512 優化（page-45）： 一次算 C 的同一個 column 裡相鄰的 8 個元素。

這些 _mm512_… 是 C intrinsics：寫起來像 function call，但 compiler 會把每一個直接換成一條對應的 SIMD instruction。目前 compiler 還不太會自己產生好的 SIMD code，所以要這樣「告訴」它。

  • __m512d：一個 512-bit 的值，裝 8 個 double；
  • _mm512_load_pd(C + i + j*n)：一次 load C[i][j] 到 C[i+7][j] 這 8 個元素。因為是 column-major，它們在 memory 裡剛好相鄰；
  • _mm512_broadcastsd_pd：把 B[k][j] 這一個數複製 8 份，填滿一個 512-bit register；
  • _mm512_fmadd_pd：8 組同時做 fused multiply-add：c0[t] += A[i+t][k] * B[k][j]，t=0,…,7t = 0, \ldots, 7t=0,…,7。

所以內層 loop 每跑一次就推進 8 個 C 元素，外層 i 每次加 8。

投影片的註解

投影片 add %r9, %rcx 的註解寫成 “%rcx = %rcx”，應該是 “%rcx = %rcx + %r9”；jne 的註解 “jump if not %r10 != %rax” 多了一個 not，應該是 “jump if %r10 != %rax”。

快多少？ 課本這一版用的是 256-bit 的 AVX（一次 4 個 double）：32 × 32 的矩陣在 2.6 GHz 的 Intel Core i7（Sandy Bridge）單核上，未優化版本是 1.7 GFLOPS（每秒十億次浮點運算），AVX 版本是 6.4 GFLOPS，快了 3.85 倍，非常接近一次做 4 個運算的理想值 4 倍。 投影片用的 AVX-512 一次做 8 個，理想上是 8 倍。

page-47–49 Fallacies and Pitfalls（§3.9）#

這些錯誤大多來自同一個根源：電腦算術的精確度有限，數學上的算術沒有這個限制。

Fallacy：左移等於乘以 2 的次方，所以右移等於除以 2 的次方（page-47）

左移 iii 位確實是乘以 2i2^i2i。右移 iii 位等於除以 2i2^i2i 只對 unsigned 成立。

Signed 的例子：−5÷4-5 \div 4−5÷4，答案應該是 −1-1−1（往 0 截斷）。8 bits 的 −5-5−5 是 11111011：

  • Logical right shift（左邊補 0，RISC-V 的 srli）：11111011 >>> 2 = 00111110 =+62= +62=+62。Sign bit 變成 0，完全錯；
  • Arithmetic right shift（左邊補 sign bit，RISC-V 的 srai）：11111011 >> 2 = 11111110 =−2= -2=−2。接近了，但還是不對。

Arithmetic right shift 是往 −∞-\infty−∞ 捨入（−1.25→−2-1.25 \to -2−1.25→−2），而除法是往 0 截斷（−1.25→−1-1.25 \to -1−1.25→−1）。所以 compiler 把 signed 除法換成右移時，負數要先加上 2i−12^i - 12i−1 再移：(−5+3)>>2=−2>>2=−1(-5 + 3) >> 2 = -2 >> 2 = -1(−5+3)>>2=−2>>2=−1。 （投影片沿用 Java 的寫法：>> 是 arithmetic、>>> 是 logical。）

Pitfall：floating-point 加法不滿足結合律（page-48）

整數加法滿足結合律，就算中間 overflow 也一樣（two’s complement 是 modulo 2n2^n2n 的運算）。Floating point 不行。例子（single precision）： x=−1.5×1038x = -1.5 \times 10^{38}x=−1.5×1038、y=1.5×1038y = 1.5 \times 10^{38}y=1.5×1038、z=1.0z = 1.0z=1.0：

(x+y)+z=0.0+1.0=1.0(x + y) + z = 0.0 + 1.0 = 1.0(x+y)+z=0.0+1.0=1.0
x+(y+z)=−1.5×1038+1.5×1038=0.0x + (y + z) = -1.5 \times 10^{38} + 1.5 \times 10^{38} = 0.0x+(y+z)=−1.5×1038+1.5×1038=0.0

1.5×10381.5 \times 10^{38}1.5×1038 比 1.0 大太多，加上 1.0 之後 round 回來還是 1.5×10381.5 \times 10^{38}1.5×1038，1.0 就這樣消失了。

這對平行程式特別麻煩：把一百萬個數分給 1 個或 1000 個 processor 加總，加的順序不同，答案就可能不同。 更糟的是，OS 每次分配的 processor 數可能不同，同樣的程式、同樣的輸入，每次跑出來的結果都略有差異。 所以平行的浮點程式要驗證結果在誤差範圍內可信，而不是要求跟循序版本完全一樣。這是 numerical analysis 的範疇，也是大家愛用 LAPACK 這類已驗證過的函式庫的原因。

Fallacy：只有理論數學家在乎浮點精確度（page-49）

1994 年的 Intel Pentium FDIV bug 證明不是。

Pentium 的除法器用 page-14 那種查表猜商的演算法（一步猜 2 bits），而表裡有 5 個 entry，Intel 的工程師以為永遠用不到，就把它們設成 0 而不是 2。結果錯了：除法結果的前 11 bits 一定正確，但第 12 到第 52 bit 偶爾會錯（大約十進位第 4 到 15 位）。

數學教授 Thomas Nicely 在 1994 年 9 月發現這個 bug，聯絡 Intel 沒得到回應，就公布在網路上，接著上了新聞。 Intel 起初說這只影響理論數學家，一般試算表使用者每 27,000 年才會遇到一次；IBM 則反駁說平均每 24 天就會遇到一次。 Intel 最後宣布免費更換，估計損失約 5 億美元。

結論：市場期待正確的答案。即使一般使用者不在乎小數點後很多位，也不接受「已知會算錯」的處理器。

page-50–51 Concluding Remarks（§3.10）#

整章的兩個重點：

1. Bits 本身沒有意義。 同一串 bits 可以是 signed 整數、unsigned 整數、floating point、字串或 instruction，意義由對它做運算的 instruction 決定。 例如 0xBF400000 用 add 看是一個負整數，用 fadd.s 看就是 −0.75-0.75−0.75（page-22）。

2. 電腦裡的數字有有限的範圍與精確度，程式必須考慮這一點：

  • ISA 支援 signed 與 unsigned 整數，以及近似實數的 floating point；
  • 範圍有限，所以運算可能 overflow 與 underflow；
  • 精確度有限，所以 floating point 的結果要 rounding，連結合律都可能不成立。

此外，subword parallelism 提供了一條簡單的路：對算術密集的程式，一條 instruction 做多個運算，就能讓 DGEMM 快上好幾倍。
