page-01–02 The Computer Revolution（§1.1）#

電腦業的進步速度遠超其他產業。課本的比喻是：如果交通業跟得上，今天從紐約到倫敦只要一秒、花一分錢。

這頁要建立的因果是：運算成本每降一個數量級，原本「做得到但太貴」的應用就會變得可行。 車用電腦、手機、人類基因組計畫、World Wide Web、搜尋引擎都是這樣出現的——技術上早就能做，卡住它們的是成本。

投影片把進步歸給兩個引擎。先定義兩個會一直出現的詞：

Definition (Transistor（電晶體）與 integrated circuit（IC，積體電路）)

Transistor 是一個由電訊號控制的開關（switch）。IC（俗稱 chip）是把大量 transistor 做在同一小塊 silicon（矽）上的元件。

  • Moore’s Law（摩爾定律）：Intel 共同創辦人 Gordon Moore 在 1965 年預測，一顆 IC 上的 transistor 數每 18–24 個月翻倍。
  • Domain-specific accelerator（領域專用加速器）：只為某一類工作（AI、繪圖、影音編碼）設計的硬體，不求通用，只求把那類工作做得又快又省電。

第二個引擎是課程自己加的。近十年 manufacturing process（製程，把電路做到 silicon 上的製造技術）的進步明顯放緩， 單靠 Moore’s Law 已經撐不住 performance（效能）的成長，業界改成把 silicon 花在專用電路上； 後面 A12 chip 上的 AI accelerator（page-19）、datacenter 裡的 accelerator（page-50）都是這條路的產物。

page-03–04 Classes of Computers#

所有電腦用的是同一套硬體技術，但不同用途要優化的目標不同，所以同一個設計決策在不同市場會有不同答案。

類別是什麼設計目標
Personal computer（PC，個人電腦）給一個人用，有螢幕、鍵盤、滑鼠，跑各式各樣的第三方軟體在有限成本下給單一使用者好的 performance
Server（伺服器）同時替多位使用者跑較大的程式，通常只透過 network（網路）存取；小到一台沒螢幕的桌機，大到整棟建築容量、performance、dependability
Supercomputer（超級電腦）最高階的 server，由數萬顆 processor（處理器）組成，做氣象預報、石油探勘、蛋白質結構這類科學計算，造價數千萬到數億美元絕對 performance；但營收只佔整個市場極小一部分
Embedded computer（嵌入式電腦）藏在其他裝置裡、只跑一個預定應用的電腦（車上、電視裡、飛機控制系統）達到門檻 performance 後，把成本與 power（功耗）壓到最低

兩個對比值得記：

  • 目標函數不同。 PC 與 server 是「預算內 performance 最大化」；embedded computer 是「performance 夠用就好，剩下全力省錢省電」。 同一顆更快的 processor，對前者是加分，對後者反而是扣分（更貴、更耗電、又用不到）。
  • Dependability（可靠度，系統持續正確運作的能力）的代價不同。 server 一當機就影響上千人， 所以願意花錢買 redundancy（備援，多放一份元件以便故障時接手）。embedded computer 最便宜卻常最不能壞（電視當機很煩，飛機當機是災難）： 消費性產品靠「設計得簡單」求可靠，大型 embedded 系統則借用 server 的 redundancy 做法。
TB 還是 TiB

儲存業者把 terabyte（TB）當成 101210^{12}1012 bytes，但傳統上它指 2402^{40}240 bytes。 為了消除混淆，現在 TB 固定是 101210^{12}1012，2402^{40}240 另稱 tebibyte（TiB）；其他前綴同理（KB/KiB、GB/GiB…）。

每升一級，二進位版本就多乘一次 1024/1000=1.0241024/1000 = 1.0241024/1000=1.024，差距會累積： KiB 比 KB 大 2%，GiB 大 7%，TiB 大 10%，到 YiB 已經大 21%。 bit 也一樣：Gb 是 10910^9109 bits，Gib 是 2302^{30}230 bits。

page-05–06 The PostPC Era#

出貨量圖顯示三件事：smart phone 在 2011 年超過 PC、tablet 成長最快、PC 與傳統手機持平或下滑。 課本認為這次轉變的份量，相當於三十年前轉向 PC 那一次。主角換人發生在兩端：

Definition (Personal mobile device（PMD，個人行動裝置）)

靠電池供電、無線連上 network、用觸控或語音操作、價格數百美元的小型裝置，例如手機、平板。

Definition (Cloud computing（雲端運算）與 warehouse scale computer（WSC，倉儲級電腦）)

Cloud computing 是透過 network 提供服務的大型 server 集合，使用者可以像水電一樣按需求租用。 撐起 cloud 的是 WSC：一座放了約 10 萬台 server 的 datacenter（資料中心），由 Amazon、Google 這類公司建造後出租。

Definition (Software as a Service（SaaS，軟體即服務）)

軟體與資料透過 network 以服務的形式提供，通常用瀏覽器存取， 而不是讓使用者下載一個在本機執行的安裝檔。網頁搜尋、社群網站都是例子。

結果是：今天的一支應用常常一半跑在 PMD、一半跑在 cloud。 所以 performance 不再只是「一台機器跑多快」：手機端在乎電池，cloud 在乎電費與 performance per watt（每瓦效能）， 兩端之間還隔著 network 的 latency（延遲，從發出請求到開始得到回應的時間）。§1.6 與 §1.7 會分別處理「快」和「省電」。

page-07–08 What You Will Learn / Understanding Performance#

1960–70 年代 performance 主要受限於 memory（記憶體）的大小，信條是「少用 memory 就會快」。今天取代它的是兩件事：

  • Processor 的 parallelism（平行性）：硬體能同時做很多件事；
  • Memory 的 hierarchy（階層）：memory 由「快而小」到「慢而大」疊成好幾層，合稱 memory hierarchy。

不懂這兩件事，想讓程式變快就只能靠試誤。這門課要回答的問題：

問題答案在
程式怎麼被翻成硬體懂的 0 與 1？硬體又怎麼執行它？Ch 2、Ch 4
軟體與硬體之間的 interface（介面）是什麼？Ch 2
什麼決定程式的 performance？程式設計師能怎麼改善？§1.6、Ch 3–6
硬體設計者怎麼提升 performance 與 energy efficiency（能源效率）？§1.7、Ch 4–6
為什麼從 sequential processing（循序處理）轉向 parallel processing（平行處理）？§1.8、Ch 6

一支程式的 performance 由四層共同決定。先簡單交代表裡的詞（後面會正式定義）： machine instruction（機器指令）是硬體能直接執行的命令；compiler（編譯器）是把程式翻成 machine instruction 的程式； architecture（架構）指硬體提供給軟體使用的那組指令；I/O（input/output，輸入輸出）例如讀寫 disk（磁碟）與 network； OS（operating system，作業系統）是管理電腦資源的程式。

page-09 Eight Great Ideas in Computer Architecture（§1.2）#

架構師幾十年累積下來的八個設計理念，全書會反覆用到：

#理念意思
1Design for Moore’s Law一個設計要做好幾年，完成時可用的 transistor 可能是開始時的好幾倍，所以要瞄準完成時的技術，像射飛靶要打在飛靶會到的位置
2Use abstraction（抽象化） to simplify design把設計分成好幾層，每層把下層細節藏起來，只提供較簡單的模型；不這樣做，設計時間會跟 transistor 數一起爆炸
3Make the common case fast優化常見情況比優化罕見情況有效，而且常見情況通常比較簡單；但得先量測才知道哪個常見
4Performance via parallelism同時做多件事
5Performance via pipelining（管線化）Parallelism 的一種特例：把工作切成幾段接力進行，像救火時排成一列傳水桶，不同工作的不同階段同時在做
6Performance via prediction（預測）先猜再做，不等確定；只要猜得夠準、猜錯的補救不貴，平均就比較快
7Hierarchy of memoriesMemory 要又快、又大、又便宜，三者互斥，所以疊成多層：最上層最快最小最貴，最下層最慢最大最便宜，常用的資料放上層，整體就像又快又大
8Dependability via redundancy實體元件一定會壞，所以放 redundancy 元件接手並偵測故障，像聯結車後軸每側兩個輪胎

投影片把標題改成 “Eight/Seven”，並在 Moore’s Law 旁邊打了問號：老師的意思是第 1 條已經不太成立了。 證據散在後面幾頁：DRAM（最常用的 memory chip，page-17）的容量成長變慢（page-24）、 processor 的 clock rate（時脈頻率，每秒跳動幾次，page-40）從 2004 年起不再上升（page-49）、 單一 processor 的 performance 成長率掉到每年 3.5%（page-52）。

page-10–11 Below Your Program / Levels of Program Code（§1.3）#

應用程式動輒數百萬行，硬體卻只能執行極簡單的 instruction，中間靠好幾層軟體翻譯——這是 abstraction 的第一個例子。 課本把它畫成同心圓：最內圈是硬體，中間是 systems software（系統軟體），最外圈是 application software（應用軟體）。

Definition (Systems software)

夾在硬體與 application software 之間、提供共用服務的軟體。最關鍵的兩種是 OS 與 compiler。

Definition (Operating system（OS）)

管理電腦資源、替上面的程式服務的監督程式。三項主要工作是：處理 I/O、 分配 memory 與儲存空間、讓同時執行的多支程式安全地共用電腦（一支不能踩壞另一支）。 例如 Linux、iOS、Windows。

Definition (Compiler)

把 high-level language（高階語言，如 C、C++、Java）寫的程式翻成硬體能執行的 instruction 的程式。

再往下一層：硬體只懂電訊號的「開」與「關」，所以電腦的字母只有兩個。

Definition (Bit 與 instruction)

Bit（binary digit，位元）是 0 或 1，資訊的最小單位。 Instruction 是硬體看得懂並照做的命令，本身就只是一串 bits，例如 1001010100101110 在某台電腦上代表「把兩個數相加」。

程式設計的歷史就是一路往上加 abstraction：

  1. 最早的程式設計師直接寫 0 與 1，太痛苦；
  2. 改用接近人類的符號記法，一開始用手翻回二進位，還是太累；
  3. 乾脆寫一支程式來翻，這支程式叫 assembler（組譯器）；
  4. 但 assembly language 一行就是一條 instruction，逼人像機器一樣思考，於是出現 high-level language 與 compiler。
Definition (Machine language、assembly language、high-level language)
  • Machine language（機器語言）：instruction 的二進位表示。
  • Assembly language（組合語言）：instruction 的符號表示，例如 add A, B。assembler 把它翻成 machine language。
  • High-level language：用單字與代數符號寫、可以被 compiler 翻成 assembly language 的語言，例如 C、Java。

有些 compiler 會跳過 assembly language 直接產生 machine language，所以「兩步」是概念上的分層，不是一定真的分兩步做。

High-level language 的三個好處強到今天幾乎沒人寫 assembly language：

  • 接近問題領域：可以針對用途設計語言（Fortran 做科學計算、Cobol 做商業資料處理、Lisp 做符號處理）；
  • Productivity（生產力）高：表達同一個想法的行數少，開發就快；
  • Portability（可攜性）：compiler 可以把同一支程式翻成任何一台電腦的 instruction。

投影片右下角的 RISC-V 是這門課用的 instruction set（指令集），第 2 章起的 assembly language 都用它。

page-12 Components of a Computer（§1.4，Big Picture）#

看完軟體，換打開機殼看硬體。任何電腦的硬體都在做四件事：輸入、輸出、處理、儲存資料。

The Big Picture：五大古典元件

電腦由 input、output、memory、datapath（資料路徑）、control（控制） 五個元件組成，後兩者合稱 processor： datapath 負責做運算，control 負責指揮其他元件該做什麼。

這個劃分與硬體技術無關，古今任何電腦的任何零件都能歸進其中一類。 所以這門課學到的原理同時適用於手機、桌機、server 與 supercomputer，差別只在規模與取捨。

資料的流向繞著 memory 轉：processor 從 memory 取 instruction 與資料，input 把資料寫進 memory， output 從 memory 讀出資料，control 送訊號決定其他四者的動作。

之所以繞著 memory 轉，是因為現代電腦都是 stored-program computer（儲存程式電腦）： instruction 和資料都以數字的形式存在同一個 memory 裡。代價是所有東西都要經過 memory， memory 的速度就成了整台機器的瓶頸——這是第 5 章的主題。

Definition (Input device 與 output device)

Input device（輸入裝置）把資訊送進電腦（鍵盤、麥克風）；output device（輸出裝置）把結果交給使用者或另一台電腦（螢幕、喇叭）。 有些裝置兩者都是，例如 network adapter（網路卡）。

投影片把 I/O 裝置分成三類：user-interface device（螢幕、鍵盤、滑鼠）、storage device（儲存裝置：硬碟、光碟、flash）、network adapter。 Flash（快閃記憶體）是一種斷電後資料不會消失的 semiconductor（半導體）memory。 Storage device 被算成 I/O，是因為 processor 不能直接存取它，要先把資料搬進 memory 才能用（page-21）。

page-13–14 Touchscreen / Through the Looking Glass#

課本從外部 I/O 裝置開始往內走，第一站是 post-PC 時代最大的改變：touchscreen（觸控螢幕）取代了鍵盤滑鼠，讓使用者直接指著想要的東西。

Touchscreen 有兩種：

  • Resistive（電阻式）：壓下去讓兩層 conductor（導體）接觸；
  • Capacitive（電容式）：人體是 conductor，在玻璃上鋪一層透明 conductor 後，手指一碰就會改變螢幕的電場，使 capacitance（電容）改變，量到變化就知道碰在哪裡。

Capacitive 量的是整片電場的分布，天生能同時偵測多點，因而支援手勢操作，所以大多數手機平板都用它。

接著是顯示器。

Definition (Liquid crystal display（LCD，液晶顯示器）)

用一層薄薄的液晶控制光線通過與否的顯示技術。LCD 本身不發光，光來自背後的背光。

原理：液晶分子排成扭轉的螺旋，會把穿過的光轉 90°；通電時分子打直，光就不再被轉。 液晶夾在兩片互相垂直的偏光板之間，所以光只有被轉過才能穿出。通電就暗、不通電就亮——voltage（電壓）控制的是閘門，不是光源，這也是它省電的原因。

Active matrix（主動矩陣） LCD 在每個 pixel 放一個 transistor 當開關來精確控制；彩色螢幕則每個 pixel 放三個，分別控制紅、綠、藍。

Definition (Pixel、bit map、frame buffer)
  • Pixel（像素）：畫面上最小的影像元素，螢幕由數十萬到數百萬個 pixel 排成矩陣。
  • Bit map（點陣圖）：用一個 bit 矩陣表示整個畫面。彩色螢幕常用每個 pixel 24 bits（紅綠藍各 8 bits）。
  • Frame buffer（畫面緩衝區）：存放 bit map 的 memory。硬體以固定的 refresh rate（更新頻率）把它的內容讀出來送到螢幕。

投影片那句 “mirrors content of frame buffer memory” 是重點：螢幕上的東西就是一塊 memory 的鏡像， 畫圖這件事被化約成「寫 memory」。

page-15–16 Opening the Box（A5、A12）#

拆開一台 iPad 2 來驗證五大元件。結果是：在這種裝置上 I/O 佔了絕大部分， datapath、control、memory 只是其中很小一塊。

  • 最上面是 capacitive 多點觸控 LCD；
  • 佔最大體積的是 3.8 V、25 Wh 的鋰電池，撐 10 小時；
  • 真正的「電腦」是電池旁邊一塊 L 形電路板，上面有 processor 與 memory；
  • 其餘是 I/O：前後鏡頭、麥克風、喇叭、Wi-Fi、藍牙、陀螺儀與加速度計（兩者合起來偵測六軸運動）。

電路板上的主 chip 是 Apple A5，裡面有兩個 1 GHz 的 ARM（一家處理器設計公司）core（核心，一個完整的 processor）， package（封裝）內還疊了 512 MB memory。 旁邊是 32 GB 的 flash chip，兩者之間留了一個空位，焊上第二顆 flash 就是 64 GB 版——同一塊板子直接對應到產品分級。

page-16 換成較新的 A12 世代：更多功能被整合進同一顆 chip，但 I/O 與電池主宰整台裝置這件事沒變。

page-17–19 Inside the Processor#

再往 processor 裡面鑽。

Definition (Central processing unit（CPU，中央處理器）)

即 processor，電腦裡主動做事的部分：做加法、比較數字、通知 I/O 裝置動作。由兩部分組成：

  • Datapath：實際做運算的部分，processor 的「肌肉」；
  • Control：依照 instruction 指揮 datapath、memory、I/O 的部分，processor 的「大腦」。

第 4 章整章就在建這兩個東西。

Definition (Memory、DRAM)

Memory 是程式執行時存放程式與資料的地方。 今天的 memory 用 DRAM（dynamic random access memory） 做成：所謂 random access，是指不論讀哪個位置， 時間都差不多，相對於磁帶那種得依序讀的 memory。

Definition (Cache、SRAM)

Cache（快取） 是 processor 裡一塊小而快的 memory，當作 DRAM 的緩衝。 它用 SRAM（static RAM） 做成：比 DRAM 快、密度低，所以每 bit 比較貴。

SRAM 與 DRAM 就是 memory hierarchy（great idea #7）的最上面兩層。

page-20 Abstractions（Big Picture）#

軟體往下走（page-10–11）與硬體往上走（page-12–19）在這裡會合： 軟硬體之間最重要的那個 interface，重要到有自己的名字。

Definition (Instruction set architecture（ISA，指令集架構）)

也直接叫 architecture。硬體與最底層軟體之間的 abstract interface， 包含寫出一支能正確執行的 machine language 程式所需的一切：有哪些 instruction、 register（暫存器，processor 內的少量高速儲存格）、怎麼存取 memory、怎麼做 I/O。

Definition (Application binary interface（ABI）與 implementation)
  • ABI：ISA 中使用者程式能用的那部分，加上 OS 提供給應用程式的 interface。它決定一個編譯好的執行檔能不能搬到另一台電腦上跑。
  • Implementation（實作）：遵守某個 architecture 的實際硬體。

ISA 與 ABI 的差別：兩台機器 ISA 相同還不夠讓執行檔直接互通， OS 的呼叫方式、函式呼叫慣例也得相同，那些都在 ABI 裡。

把 architecture 與 implementation 分開，就像討論數位時鐘時可以只談「報時、顯示、鬧鈴」這些功能， 不必談石英、LED、塑膠按鈕。

The Big Picture

硬體與軟體都由一層層的 abstraction 組成，每一層對上一層隱藏細節。 其中最關鍵的 interface 是 ISA：因為 ISA 固定，成本與 performance 各異的多種 implementation 才能跑同一套軟體。 例如 Intel 與 AMD 的 processor 內部設計完全不同，但都 implement x86 這套 ISA，所以軟體不必各編一次。

page-21 A Safe Place for Data#

到目前為止的 memory 一斷電就忘光。要把程式與資料留到下次，需要另一種 memory。

Definition (Volatile / nonvolatile memory)

Volatile（揮發性） memory 只在通電時保住資料，例如 DRAM； nonvolatile（非揮發性） memory 斷電後資料仍在，例如 DVD。

Definition (Main memory 與 secondary memory)

Main memory（主記憶體） 放執行中的程式，今天用 DRAM。 Secondary memory（次要記憶體） 是 nonvolatile 的，在兩次執行之間保存程式與資料：PMD 用 flash，server 用 magnetic disk。 Secondary memory 構成 memory hierarchy 的下一層。

page-22 Networks#

就像匯流排把 processor、memory、I/O 連起來，network 把整台電腦連起來。它帶來三個好處： communication（電腦間高速交換資訊）、resource sharing（不必每台都配齊 I/O 裝置）、nonlocal access（不必坐在電腦前面）。

通訊成本隨速度與距離一起上升，所以 network 分成兩種：

Definition (LAN 與 WAN)
  • Local area network（LAN，區域網路）：限於一個小區域（通常一棟建築）的 network。最常見的是 Ethernet，長度可達 1 公里、最高 40 Gbps，多個 LAN 用 switch（交換器，在多台電腦之間轉送資料的裝置）互連。
  • Wide area network（WAN，廣域網路）：延伸數百公里、可橫跨大陸的 network，通常用向電信公司租的光纖，是 Internet 的骨幹。

1970 年代幾乎沒有 LAN，要在兩地之間傳大量資料得把磁帶寄過去； 三十年前的 Ethernet 是 10 Mbps、由數十台電腦共用，今天是 1–40 Gbps、只由幾台共用。

Wireless network（無線網路，今天的 Wi-Fi 標準叫 IEEE 802.11）催生了 post-PC 時代。 關鍵在於無線電能用與 processor、memory 同一種低成本製造技術（CMOS，§1.7 介紹）來做，價格因此大降。 它與有線 network 的根本差別是同一區域的使用者共用同一段電波。

投影片補的當代數字：datacenter 的 Ethernet 到 100–800 Gbps，NVIDIA 用來在機器內連接 GPU 的 NVLink 則到 1800 GB/s。 注意單位：1800 GB/s（bytes）等於 14,400 Gbps（bits），是 800 Gbps Ethernet 的 18 倍——距離越短，能給的 bandwidth（頻寬）越高。

page-25 Semiconductor Technology#

Chip 從 silicon 開始，silicon 是沙子裡就有的元素。

Definition (Semiconductor)

導電性不好也不差的物質。Silicon 就是 semiconductor。

「不上不下」反而是優點：摻入特定材料後，可以把 silicon 上的微小區域變成三種東西之一—— conductor（微觀的銅線或鋁線）、insulator（絕緣體，像塑膠或玻璃）、或在特定條件下才導電的區域，也就是 switch（transistor）。 一顆 VLSI chip 就是幾十億個 conductor、insulator 與 switch 做在一個小 package 裡。

VLSI 這個名字的由來：早期 IC 一顆只有數十到數百個 transistor。Moore 預測的正是每顆 chip 上的 transistor 數量， 當數量漲到數十萬、數百萬，就在名字前加上 very large scale。

page-26–27 Manufacturing ICs / Wafer and Chips#

Manufacturing process 決定 chip 的成本，所以設計者得懂。

Definition (Ingot、wafer)

Silicon crystal ingot（矽晶柱） 是直徑 8–12 吋、長 12–24 吋的 silicon 晶體棒。把它切成不到 0.1 吋厚的薄片，就是 wafer（晶圓）。

Wafer 經過 20–40 道步驟，把化學圖案一層層做上去，形成 transistor、導線與 insulator。 Transistor 只有一層（必須做在 silicon 表面），連接它們的金屬導線則有 2–8 層。所以 transistor 數量取決於面積。

每一步都可能留下微觀的 defect（瑕疵），做出一片完美的 wafer 幾乎不可能。對策是在一片 wafer 上做很多顆獨立的 chip，壞的丟掉就好：

Definition (Defect、die、yield)
  • Defect：wafer 或 processing step 中的微觀缺陷，會讓含有它的那一顆 chip 失效。
  • Die（晶粒）：從 wafer 上切下的一個個矩形，也就是 chip。
  • Yield（良率）：良品 die 佔全部 die 的比例。

課本的例子：一片 wafer 切出 20 顆 die，17 顆通過測試，yield 85%。 切割前先測一次，畫出哪幾顆是好的，免得把壞 die 拿去 package（package 要花錢）； bonding（接合，把 die 接到 package 的接腳上）過程本身也會出錯，所以出貨前再測一次，這次又抓到 1 顆壞的。

Definition (Feature size（特徵尺寸）)

「32 nm process」指 die 上最小的特徵約 32 nm。但這是設計圖上的尺寸，實際做出來的通常更小， 所以「幾奈米」比較像 process 世代的代號，不同廠商的同一個數字未必可比。

page-37–39 Measuring Execution Time / Performance Monitoring Tools#

「時間」要看算進哪些東西：

  • Elapsed time（又稱 wall clock time 或 response time）：從開始到結束的總時間，包含 I/O、OS 開銷、等待，全部都算。
  • CPU time：CPU 真正花在這支程式上運算的時間，不含等 I/O、不含跑其他程式。電腦常被多支程式共用，所以需要這個區分。
    • User CPU time：花在程式本身；
    • System CPU time：OS 替這支程式做事的時間。這兩者很難分準，因為 OS 的工作不一定能歸給某一支程式。

使用者感受到的永遠是 elapsed time；CPU time 是設計者用來分析 processor 的工具。 課本把「沒有其他負擔時的 elapsed time」叫 system performance，把 user CPU time 叫 CPU performance，本章專注在後者。

投影片最後一行 “different programs are affected differently” 的意思是：有的程式卡在 CPU，有的（尤其 server 程式）卡在 I/O。 所以改善 performance 的流程是：先決定哪個指標重要，再量測、找出瓶頸。

page-38 是 Brendan Gregg 的 Linux performance 工具全景圖：把系統由應用程式、system call、scheduler、memory、file system、network 一路畫到硬體， 每一層旁邊標出量它用的工具（top、vmstat、iostat、strace、perf…）。 page-39 是 Intel 的圖形化分析工具 VTune，可以直接看到每一行程式碼花了多少時間。 其中 perf stat ./a.out 能直接印出程式執行了幾條 instruction、花了幾個 clock cycle（下一頁定義）——page-43 會用到這兩個量。

page-43–46 Instruction Count and CPI#

上面的式子看不出 instruction 的數量。但程式就是一條條 instruction，execution time 當然跟它有關。先定義兩個量：

Definition (Instruction count（IC）與 CPI)
  • Instruction count：程式實際執行的 instruction 數（執行時跑了幾條，不是程式碼裡寫了幾條）。 注意這裡的 IC 跟 integrated circuit 同縮寫，§1.6 以後的 IC 都是 instruction count。
  • CPI（clock cycles per instruction）：程式執行時，平均每條 instruction 花幾個 clock cycle，也就是「總 clock cycle 數 ÷ IC」。 不同 instruction 花的 cycle 不同，所以 CPI 是平均值。
CPI 是「某支程式在某台機器上」的值

同一台機器跑不同程式，CPI 不同（page-55 的表上從 0.32 到 1.32）； 同一支程式換一台機器（即使 ISA 相同）、換 compiler，CPI 也會變。所以講 CPI 一定要說清楚是哪支程式、哪台機器。

於是

CPU clock cycles=Instruction count×CPI\text{CPU clock cycles} = \text{Instruction count} \times \text{CPI}CPU clock cycles=Instruction count×CPI

誰決定誰：IC 由程式、ISA、compiler 決定；CPI 由 CPU 硬體決定，但既然是平均，也會受到各種 instruction 所佔比例的影響。

Definition (Instruction mix（指令組合）)

程式執行時各類 instruction 所佔的比例。

同一個 ISA、同一支程式，IC 必然相同，這時比 CPI 才有意義；跨 ISA 比 CPI 沒有意義，因為一邊可能一條 instruction 就做完另一邊三條的事。

有些 processor 每個 clock cycle 能執行好幾條 instruction（第 4 章），CPI 可以小於 1，這時常改講 IPC（instructions per clock cycle）= 1 / CPI。

State 只在 clock cycle 邊界更新，CPI 怎麼可能小於 1？

一條 instruction 從開始到完成確實至少要一個 clock cycle，但 CPI 量的不是單一 instruction 的 latency， 而是「總 clock cycles ÷ IC」這個平均，比較接近 page-33 說的 throughput。

邊界更新這條規則限制的是「什麼時候寫入」，沒有限制「一次寫幾條」。 Multiple issue（多發射）的 processor 裡有好幾組運算單元，同一個 clock cycle 裡可以讓幾條彼此不相依的 instruction 各自算完， 在同一個邊界一起把結果寫進 register。每個 cycle 最多完成 4 條的 processor，CPI 理論上可以低到 0.25。

前提是程式裡要有足夠多彼此不相依的 instruction：如果下一條要用到上一條的結果，就只能等它做完。

Processor 消耗的 power 最後全部變成熱，而用一般商用的散熱方式（散熱片加風扇），一顆 chip 每秒能排掉的熱有上限， 桌機 processor 大約在 100 W 上下（上表 2004 年後都停在 84–103 W）。 Power 不能超過這個上限，這道上限就叫 power wall。

為什麼 power wall 擋住了提高 clock rate 這條路：

  1. Frequency switched 與 clock rate 成正比。在 CCC、VVV 不變的情況下，clock rate 提高幾倍，power 就跟著提高幾倍。
  2. 過去 clock rate 能一路提高而 power 沒有失控，靠的是每一代都降 voltage：V2V^2V2 的下降抵掉了 clock rate 的上升。
  3. 到了 2004 年左右，power 已經頂到約 100 W 的散熱上限，沒有空間再讓它上升； 而 voltage 也已經降到約 1 V，再降下去 transistor 會產生嚴重的 leakage（漏電：transistor 關著時仍有電流漏過，page-51）， 所以 VVV 也降不動了。
  4. VVV 降不動、power 又不能再升，式子裡剩下的 frequency switched 只要再提高，power 就會超過散熱上限。 於是 clock rate 停在 3–4 GHz：上表 2004 年的 Prescott 是 3600 MHz，14 年後的 Coffee Lake 還是 3600 MHz。

page-49 說 power wall 讓 clock rate 無法再提高；這頁補上兩個出口為什麼都堵住了。

  • Voltage 降不下去：再降，leakage 會變得很嚴重，transistor 像關不緊的水龍頭。今天 server chip 約 40% 的 power 來自 leakage。
  • 熱排不掉：已經裝了大型散熱器、也在每個 clock cycle 關掉沒用到的電路；更貴的冷卻方式（例如能撐到 300 W 的那種）對 PC 甚至 server 都不划算。

Static energy（靜態能量）。 前面的 dynamic energy 只在 transistor 切換 0/1 時才花。 但因為 leakage，只要 transistor 接著電源，就算它停在 0 或 1 完全不切換，也一直有電流漏掉、一直在耗電。 這部分就是 static energy：它跟電路有沒有在工作無關，只跟「有多少 transistor 接著電」有關。

這帶來一個後果：

  1. 每一代 process 都讓一顆 chip 能放更多 transistor；
  2. 但 power 的上限（power wall）沒有跟著變高，而每一顆接著電的 transistor 都在耗電（有在切換的還要再加上 dynamic energy）；
  3. 所以 transistor 多到一個程度後，就不能讓整顆 chip 同時通電運作，否則 power 會超過上限；
  4. 解法是把暫時用不到的電路區塊整塊斷電，連電源都切掉，這樣連 leakage 都沒有。 這些做在 chip 上、但某個時刻被斷電的區域叫 dark silicon（暗矽）。

既然 chip 上總有一部分得斷電，與其放很多份一樣的通用電路（反正不能同時全開）， 不如放幾種不同的專用電路，例如影片解碼、AI 運算用的 accelerator，做哪種工作就只替那一塊通電。 這樣被斷電的面積也沒有白放，這是業界走向 accelerator 的另一個理由。

撞上 power wall 之後，設計者只好換一條路：投影片最後一句 “How else can we improve performance?” 就交給 §1.8。

前半段是 processor 的黃金時代。 1986 年以後，架構師把 pipelining、prediction、cache 這些想法（great ideas #5–#7） 放進 processor，讓 performance 從每年 25% 提升到 52%。課本算過：如果一直停在 25%， 2002 年的 performance 只有實際的七分之一——多出來的那一大截全是 architecture 的功勞，這也是這門課值得學的原因。

2003 年之後斜率一路往下掉。 投影片下方的藍框說，是三道限制同時撞上了：

  1. Power：就是 page-49 的 power wall，clock rate 不能再拉。
  2. Instruction-level parallelism（ILP，指令層級平行）：黃金時代的另一招，是讓硬體在一支程式裡同時執行好幾條 instruction， pipelining 就是一例。但一支程式裡「彼此不相依、可以同時跑」的 instruction 就那麼多， 挖到後來，再加硬體也挖不出更多。（第 4 章）
  3. Memory latency：processor 每年快 50%，DRAM 的存取時間卻幾乎沒變短。 processor 越快，花在等 memory 的時間比例就越高，cache 也只能掩蓋一部分。（第 5 章）

把三條合起來看：拉 clock rate、挖 ILP、用 cache 蓋住 memory 的慢，這三條讓單一 processor 變快的路同時走到了盡頭。 所以產業只剩一個選擇：不再想辦法讓一個 processor 變快，改成在一顆 chip 上放好幾個 processor，這就是下一頁的 multicore。 這個轉向大到課本把這一節叫做 “The Sea Change”（翻天覆地的轉變）。

代價落在軟體身上。課本引 Brian Hayes 的比喻：過去的軟體像寫給獨奏者的曲子， 現在開始要寫二重奏、四重奏，而替整個管弦樂團寫譜，是完全不同等級的挑戰。

page-53 Multiprocessors#

上一頁的結論是：單一 processor 已經快不起來了。產業的回答很直接——從 2006 年起， 所有桌機與 server 廠商賣的都是一顆 chip 裡有好幾個 processor 的產品。

Definition (Multicore microprocessor（多核心處理器）)

Microprocessor（微處理器）是做在一顆 chip 上的 processor；multicore microprocessor 就是一顆 chip 裡放了好幾個 processor。 為了不跟 microprocessor 混淆，chip 裡的每個 processor 改叫 core，所以 quadcore 就是有四個 core 的 chip。

這一步看起來只是硬體換了設計，真正的衝擊在軟體。以前程式一行都不用改，只要等新的 processor 出來， 每 18 個月就自動快一倍。現在不行了：多出來的 core 只能讓電腦同時做更多件事，一支沒改過的程式還是只用得到其中一個 core。 所以 multicore 首先改善的是 throughput（同時跑很多程式），而不是單一程式的 response time。 想讓一支程式本身變快，程式設計師得把它改寫成 parallel 版本，而且 core 數每增加一次，就得再調整一次。

這裡值得停下來比較兩種 parallelism，因為它說明了這次轉變為什麼痛苦：

ILP 也是 parallelism，但硬體把它藏得很好——這是 abstraction 最成功的例子之一。 Multicore 則讓這層 abstraction 藏不住了：平行這件事必須由寫程式的人自己處理。 課本特別提到，過去凡是要求程式設計師改變寫法的公司都失敗了，而這次整個產業卻把未來押在這件事上。

為什麼 parallel programming 這麼難？ 課本給了兩個原因：

  1. 寫 parallel program 的唯一目的就是 performance：它不只要正確，還必須真的變快，不然直接寫 sequential program 就好。
  2. 要真的變快，就得把工作切成每個 core 分量差不多，而且 core 之間協調的成本不能把好處吃光。

每一章最後都有一節 Fallacies and Pitfalls，專門講常見的錯誤。先分清楚兩個詞：

  • Fallacy（謬誤）：一個常見但錯誤的觀念。課本的做法是舉反例推翻它。
  • Pitfall（陷阱）：一個很容易犯的錯，通常是把只在某些情況下成立的原則，套用到不適用的地方。

第一個 pitfall 是設計者最常踩的：

Pitfall

以為改善電腦的某一部分，整體 performance 就會按改善的比例提升。

直覺上，把某個部分加速 10 倍，整體好像也該快很多。但如果那部分本來只佔一點點時間呢？Amdahl’s Law 把這件事寫成了公式：

page-62 Fallacy: Low Power at Idle#

接下來兩個 fallacy 都跟 energy 有關。第一個：

Fallacy

Utilization（使用率）低的電腦耗電很少。

聽起來理所當然：沒在做事，應該就不太耗電。但 page-57 的表已經給了反例：10% load 仍吃峰值的 33%，完全閒置也吃 14%。 投影片另一組 i7 的數字更糟：100% load 258 W、50% load 170 W（66%）、10% load 121 W（47%）。

這為什麼重要？因為真實的 server 大部分時間正好落在低 load：Google 的 server 大多在 10–50% load，滿載的時間不到 1%。 也就是說，datacenter 幾乎總是在效率最差的區間運作。而且上面還是特別為 benchmark 調校過的機器，一般現場的機器只會更糟。

背後的原因之一就是 page-51 的 leakage：只要 chip 通電就一直在漏，跟 load 無關。 所以 Barroso 與 Hölzle（2007）主張 energy-proportional computing（能源比例運算）：重新設計硬體，讓 power 跟著 load 成正比。 如果 10% load 只吃 10% 的電，datacenter 的電費與碳排都會大幅下降。

page-63 Fallacy: Performance and Energy Efficient#

第二個 fallacy 跟 energy 有關，但方向相反：

Fallacy

為 performance 而設計與為 energy efficiency 而設計是不相關的目標。

很多人的直覺是：讓程式變快是一回事，讓它省電是另一回事，甚至兩者互相衝突——想快就得多耗電。 課本要說的是：兩者其實高度相關，讓程式跑得更快，通常也就更省 energy。

關鍵在 page-49 的 E=P×TE = P \times TE=P×T，而且這裡的 PPP 要算整台電腦，不只是 processor。 程式在跑的這段時間，memory、disk、電源供應器等其他元件也一直在耗電。 程式早一點跑完，這些元件耗電的時間就縮短，它們的 energy 也就跟著省下來。

用數字看一次。假設一台電腦跑某支程式：

Processor 的 power其他元件的 powerExecution time總 energy
優化前50 W50 W10 s(50+50)×10=1000(50 + 50) \times 10 = 1000(50+50)×10=1000 J
優化後60 W50 W6 s(60+50)×6=660(60 + 50) \times 6 = 660(60+50)×6=660 J

這個優化讓 processor 更耗電（50 W → 60 W），但程式從 10 秒縮到 6 秒，總 energy 反而少了三分之一。 省下來的主要來自兩處：processor 自己的 energy 從 500 J 降到 360 J（power 多 20%，時間卻少 40%）， 其他元件的 energy 從 500 J 降到 300 J（power 沒變，單純是時間變短）。

所以只看 power（watt）會以為這個優化比較耗電，看 energy（joule）才知道它其實更省——這也是 page-49 說 joule 比 watt 更好的原因。

實務上這個想法叫 race to idle：與其慢慢做，不如全速把工作做完，然後盡快讓電腦進入低耗電的休眠狀態。 不過這招要有效，前提是休眠時真的省電。上一頁剛說過，server 閒置時仍然吃掉峰值 power 的 14%， 而原因之一就是 leakage。兩頁合起來的結論是：忙的時候要快，閒的時候要睡得夠深。

page-64 Pitfall: MIPS as a Performance Metric#

最後一個 pitfall 回到 performance 的量法：

Pitfall

只用 performance equation 的一部分當 performance 指標。

page-47 說過只有 execution time 可靠，只看 clock rate、IC、CPI 其中一個會出錯。 這一頁要說的是：就算看了其中兩個，一樣會出錯。最經典的例子是 MIPS。

IC 被約掉了。MIPS 其實只看 clock rate 與 CPI，完全看不到程式執行了多少條 instruction。這導致三個問題：

  1. 不能跨 ISA 比較。 它不管每條 instruction 做了多少事：一台用三條簡單 instruction、另一台用一條複雜 instruction 做同一件事，前者的 MIPS 會高三倍。
  2. 一台電腦沒有單一的 MIPS。 CPI 隨程式變（page-55 差 4 倍），MIPS 也跟著變。
  3. 可以跟 performance 反向變動。 程式執行更多 instruction、但每條更快時，MIPS 升高，程式卻可能變慢。

page-65 Concluding Remarks（§1.12）#

最後把整章收起來。課本的結論可以濃縮成七點，每一點都是前面某一段的總結：

  1. Cost/performance 持續改善，動力來自底層技術的進步（§1.5）。
  2. 軟硬體都是一層層的 abstraction（§1.3、§1.4），但這不代表設計者只懂一層就夠——不懂 cache，就拿不到 page-59 那幾十倍。
  3. ISA 是 hardware/software interface（page-20）：固定住它，成本與 performance 各異的 implementation 就能跑同一套軟體； 代價是需要改 interface 的創新會被擋住。
  4. Execution time 是唯一有效的 performance 指標（§1.6）。失敗的指標有兩種：一開始就不反映 execution time（MIPS）， 或在有限情境下正確、卻被用到情境之外（只比 CPI、只看滿載 power）。
  5. Energy efficiency 取代了 die area，成為 processor 設計最稀缺的資源（§1.7、§1.8）。 省電的壓力讓硬體轉向 multicore，進而逼軟體轉向 parallel programming：parallelism 現在是 performance 的必要條件。
  6. 組織設計上兩個關鍵想法：利用程式的 parallelism（通常靠多個 processor）， 以及利用 memory 存取的 locality（局部性，最近用過的資料和它附近的資料很可能馬上再被用到）（通常靠 cache）。
  7. 好的設計要針對目標市場，在成本、performance、energy、dependability、擁有成本、擴充性之間取得平衡——這又回到了 page-03 的分類。

  • EDVAC 與 stored-program：團隊討論把程式當數字存起來，von Neumann 把想法寫成備忘錄，散發時只掛了他的名字。 「von Neumann computer」一詞由此而來；課本認為這對實際造機器的 Eckert 與 Mauchly 不公平，所以全書不用這個詞。
  • EDSAC（1949，劍橋）：第一台全尺寸、可運作的 stored-program computer。
  • Harvard architecture：當年指 instruction 與資料用分開的 memory；今天的意思變成「同一個 main memory，但 instruction 與資料有各自的 cache」。
  • Whirlwind（MIT）：發明了 magnetic core memory（磁芯記憶體），當了將近 30 年的 main memory 技術。
