page-22#

User Identification in UNIX#

UNIX 是多人系統，所以系統必須先知道「你是誰」，才能決定你能碰哪些東西。這頁講的就是登入（logging in）時系統查的那份帳號資料。

/etc/passwd#

一個純文字檔，一行一個帳號，欄位用 : 分隔，共七欄。投影片的例子：

欄位例子意思
Login-nameroot登入用的帳號名稱
encrypted passwdx加密後的密碼。現在都寫 x，表示真正的密碼放在 /etc/shadow
numeric user-ID（UID）0系統內部真正用來辨識使用者的數字，kernel 只認 UID 不認名字。0 是 root，也就是權限最大的超級使用者
numeric group ID（GID）1所屬群組的編號，用來做一群人共用的權限
commentSuper-User說明欄，通常放全名或用途
home dir/root登入後所在的目錄
shell program/bin/tcsh登入後幫你啟動哪一支 shell（ch00 page-07：shell 是命令解譯器）
  • local machine or NIS DB：帳號資料可以放在這台機器自己的 /etc/passwd，也可以放在 NIS（Network Information Service）這種集中式資料庫——整個網路的機器共用同一份帳號資料，不必每台各自維護。

/etc/shadow#

/etc/passwd 必須人人可讀（很多程式要靠它把 UID 換成使用者名稱），但這樣等於把加密後的密碼送給攻擊者慢慢猜。所以密碼欄改成 x，真正加密後的密碼移到 /etc/shadow，這個檔只有 root 讀得到。

Related shell command#

passwd：改自己的密碼。

page-23#

cat /etc/passwd#

cat（concatenate）把檔案內容印到螢幕上。這頁就是真的印出來看一台機器上的 /etc/passwd 長什麼樣。

可以觀察到的幾件事：

  • 大部分帳號不是給人用的：daemon、bin、sys、mail、www-data、backup 這些都是系統服務專用的帳號。每個服務用自己的低權限帳號去跑，萬一被攻破，攻擊者也只拿到那個帳號的權限，不會直接變成 root（ch00 page-19 的 Protection / Security）。
    • daemon：在背景常駐執行的程式，例如網頁伺服器、印表機服務。
  • 第二欄全是 x：密碼都搬到 /etc/shadow 了。
  • root 的 UID 和 GID 都是 0。
  • nobody 的 UID 是 65534：權限最小的帳號，給完全不需要權限的程式用。
  • 第七欄不一定是 shell：sync 這個帳號的第七欄是 /bin/sync。

第七欄怎麼拿來擋登入#

第七欄真正的定義是：驗證通過後，系統要幫你執行哪一支程式。平常放 shell，你才會拿到那個可以一直打指令的介面；換成一支做完就結束的程式，密碼對了也待不住：

第七欄登入後會發生什麼
/bin/bash進入 shell，可以一直打指令
/bin/sync執行 sync（把還沒寫回硬碟的資料寫回去）就結束，連線隨即斷掉
/usr/sbin/nologin印一行「This account is currently not available.」就結束
/bin/false什麼都不印，直接以失敗結束

現在的系統會把服務帳號設成 /usr/sbin/nologin，這份投影片比較舊，所以那些帳號還寫著 /bin/sh。不過這只擋互動登入，帳號本身還是活的：系統服務照樣用它的身分在背景跑。

而「沒有 shell 的帳號」有兩種情況。第七欄真的空白時 不會 擋登入，login 會改用預設的 /bin/sh；真正登不進去的通常是密碼被鎖住——/etc/shadow 的密碼欄寫 * 或 !，代表沒有任何輸入算得出這個值，所以永遠比對不過。服務帳號多半兩招一起用。

Password Encryption and Salt#

密碼不是明文存的，存的是 crypt() 算出來的結果。這個運算是單向的：能拿密碼去算結果，不能從結果反推回密碼。登入時系統把你輸入的密碼再算一次，比對兩個結果一不一樣。

  • crypt(3) is designed to make a key search computationally expensive crypt 是 C library 的函式（(3) 是 man 的第 3 章，見 page-25）。它被刻意設計成算起來很慢，這樣攻擊者要一個一個試密碼（key search）就得花上大量時間。

  • /bin/passwd selects a salt based on the time of day 你設定密碼時，passwd 會依「當下的時間」挑一個 salt，轉成兩個字元的字串。

  • Salt is converted into a two character string and stored in the encrypted password file crypt(密碼, salt) 的結果前兩個字元就是 salt 本身，跟著一起存進密碼檔，之後驗證才知道該用哪個 salt 重算。

  • Salt makes it harder for an attacker to build a reverse dictionary reverse dictionary 是攻擊者預先算好的對照表：常見密碼 → 加密結果，拿到密碼檔就能直接查。有了 salt，每一個 salt 都要各算一整本表，成本暴增。

  • allows users to use the same password on different computers 同一組密碼配上不同的 salt，存出來的結果完全不同。所以同一個人在不同機器用同一組密碼，從密碼檔也看不出來它們是一樣的；同一台機器上兩個人密碼相同，也不會長得一樣。

NOTE

現在的系統已經不用這種兩字元 salt 的舊做法了，改用 SHA-512、bcrypt、yescrypt 這類演算法，salt 長很多。/etc/shadow 裡 $6$ 開頭就代表 SHA-512。但 salt 的用意跟這頁講的完全一樣。

man 3 crypt#

man（manual）用來查線上手冊：man 指令或函式名稱 就會顯示它的用法。

手冊分成 8 章（section）。同一個名字可能在不同章各有一篇，所以要用數字指定要查哪一章：

Section內容
1一般指令（在 shell 打的那些，例如 ls、cat）
2System calls
3Library 函式，特別是 C 標準函式庫
4特殊檔案（/dev 底下的裝置）與 driver
5檔案格式，例如 man 5 passwd 就是在講 /etc/passwd 的七個欄位
6遊戲與螢幕保護程式
7雜項
8系統管理指令與 daemon

所以 man 3 crypt 查的是「C library 裡的 crypt 函式」。平常看到的 crypt(3)、read(2)、printf(3) 寫法，括號裡就是章號——從章號就能看出它是 system call 還是 library 函式，正好對應 ch00 page-16：read(2) 是 system call，printf(3) 是包在上面的 library 函式。

man -k 關鍵字 可以用關鍵字反查有哪些手冊頁。

page-27#

Programs and Processes#

  • Program：躺在硬碟上的一個可執行檔（executable file），是靜態的資料。
  • Process：program 被載入記憶體、正在執行中的一份實例（ch00 page-07：a program in execution）。每個 process 有一個唯一的 process ID（PID），kernel 用它來指名道姓。
  • 同一支 program 可以同時有很多個 process：同一個編輯器開兩次，就是兩個 process，各自有自己的記憶體和 PID。

相關指令：

  • ps：印出目前 process 的快照（snapshot），印完就結束。
  • top：持續更新地顯示 process 和它們的 CPU、記憶體用量。

page-28#

CPU Scheduling#

決定「哪個 process 可以占用資源」——資源可以是 CPU，也可以是磁碟等等。

圖的比喻：CPU 是那支遊戲手把，三個小孩是三個 process，大家都想玩（都想執行），但手把只有一支，所以要有人決定 Whose turn is it? 做這個決定的就是 kernel 裡的 scheduler。

  • User can change a process priority：使用者可以調整 process 的優先權，讓 scheduler 比較早／比較晚挑到它。
  • 相關指令 nice：啟動一支程式時順便指定它的 nice 值，例如 nice -n 10 ./myprogram。
    • nice 值的範圍是 -20 到 19，預設 0。數字越大，優先權越低（越願意禮讓別人），數字越小優先權越高。
    • 一般使用者只能把自己的 nice 值調大（自願降低優先權），要調成負的必須是 root，否則人人都把自己設成最高優先權就失去意義了。
    • 已經在跑的 process 要改用 renice。

Example of Multitasking#

一整段動畫，用彩色長條代表 process，演一遍它們在系統裡怎麼流動。兩張字幕分別定義：

  • Time sharing（page-29）：CPU 的時間被切開來分給多個工作，看起來像同時進行。
  • Context switch（page-35）：把一個 process 的執行狀態存起來、再把另一個 process 的狀態載回來的過程。

畫面上的零件#

零件功能
Start（左上方框）process 的誕生處。新的 process 從這裡進入系統
Ready Queue「可以執行、但還沒輪到」的 process 排隊的地方
CPU（紫色圓）正在執行的 process。一次只容得下一個
Exit（右上箭頭）執行完畢的 process 從這裡離開系統
Time Slice（中間那條長回程）時間片用完、被換下來的 process 走的路，終點是 ready queue
Event Queue「在等某件事發生、還不能執行」的 process 待的地方，例如等磁碟把資料讀好
Event（左下紫色橢圓）事件真的發生的那一刻。process 經過這裡就代表它等到了
彩色長條一支 process。動畫全程顏色不變，可以靠顏色追蹤同一支 process

搬移規則#

兩個佇列都是 從尾端進、從前端出：ready queue 左邊是尾端、右邊是前端；event queue 右邊是尾端、左邊是前端。

叫 queue，但不一定照順序處理

event queue 裡誰先走，看的是 誰等的事件先發生，跟排隊順序無關。等磁碟的可能比早就在排隊、等鍵盤輸入的更早等到。

那為什麼還叫 queue？因為真正的系統裡沒有「一個」event queue：kernel 是每一種事件各維護一條等待佇列——等這顆磁碟的一條、等鍵盤的一條、等某支子 process 結束的一條。同一條佇列裡等的是同一件事，事件發生時確實照順序叫醒；會看起來像插隊，是因為投影片把所有佇列畫成同一個框。queue 在這裡指的是 kernel 用來掛住這些 process 的串列，不是「先到先服務」的保證。

同理，ready queue 也不是嚴格先到先服務：scheduler 挑人時會看優先權（page-28 的 nice）。投影片畫成單純排隊是簡化過的。

路徑什麼時候走
Start → ready queue 尾端新的 process 被建立
ready queue 前端 → CPUscheduler 挑中它（dispatch）。CPU 換人的這一刻就是 context switch
CPU → Exit程式跑完了，離開系統
CPU → Time Slice → ready queue 尾端時間片用完被換下來。它 還能跑，只是得重新排隊
CPU → event queue 尾端它要等 I/O（例如 read 要等磁碟），在等到之前 不能跑
event queue 前端 → Event → 左側路徑 → ready queue 尾端等的事件發生了。注意它不會直接回到 CPU，一樣要重新排隊

動畫逐格#

起始狀態（page-29）：ready queue 由尾到前是橘、黃綠、深綠；CPU 空著；event queue 由前到尾是淡紫、紅、暗紅、藍灰。

page-43：三個狀態#

最後一張把畫面上的三個位置正式命名，並附上狀態圖：

位置狀態意思
Ready QueueReady可以執行，只差沒輪到 CPU
CPURunning正在執行
Event QueueBlocked在等某個事件，例如等磁碟把資料讀好。資料還沒來，它的下一行程式就沒辦法往下跑，所以 scheduler 不會挑它——給它 CPU 也只是白白占著

投影片上四個黃色數字就是四種轉換：

編號轉換圖上的路徑
1Process blocks for input（Running → Blocked）CPU 右側往下進 event queue
2Scheduler picks another process（Running → Ready）Time Slice 那條回程
3Scheduler picks this process（Ready → Running）ready queue 前端進 CPU
4Input becomes available（Blocked → Ready）Event 往上回 ready queue

注意沒有 Blocked → Running 這條路：等到事件的 process 一定要先回 Ready 排隊，不會直接搶回 CPU。

回頭對照 ch00 的兩個例子：page-15 的 sleep 5 就是主動讓自己變成 Blocked（所以那 5 秒 user 時間是 0）；ch00 page-10 講的 context switch，發生的時機就是這裡的轉換 2 和 3。

UNIX Process：shell 怎麼幫你執行指令#

Shell 是 command interpreter（命令解譯器，ch00 page-07）：你打 ls、pwd，它負責找到那支程式並讓它跑起來。圖畫的就是這個過程，四個圈都是 system call。

步驟誰做的發生什麼
forkshell process複製出一個幾乎一模一樣的 child process：記憶體內容、開著的檔案都複製一份。從這裡開始分岔成兩條路，上面虛線是原本的 shell（parent process），下面實線是 child
execve()child把自己的記憶體內容整個換成 /bin/ls 這支程式。PID 不變，但執行的程式變了——child 從「shell 的分身」變成 ls
exitchildls 跑完，結束自己並回傳一個狀態碼
waitparentshell 在這裡停下來等 child 結束。child 一 exit，wait 就返回，shell 印出提示字元，繼續等你下一個指令

所以打完 ls 之後 shell 還在，是因為真正去執行 ls 的是 child，shell 自己只是等。指令後面加 & 改成背景執行，差別就在 shell 不 wait，直接回來接受下一個指令。

用 page-43 的狀態來看：wait 期間 shell 在等「child 結束」這個事件，所以它是 Blocked。

page-45#

A Process Tree#

每個 process 都是別的 process fork 出來的，所以全系統的 process 構成一棵樹：

  • A 建立了 B、C 兩個 child
  • B 又建立了 D、E、F 三個 child

樹根是開機時 kernel 建立的第一支 process（Linux 上是 systemd 或 init，PID 1），其他所有 process 都是它的後代。

每個 process 除了自己的 PID，還記得 parent 的 PID（PPID）。這條關係是必要的：wait 要知道該等誰、child 結束時要通知誰。想看這棵樹可以用 pstree，或 ps -ef 看 PPID 欄。

page-47#

Inter-process Communication#

  • Pipe（|）：把左邊指令的輸出接到右邊指令的輸入。兩支程式是同時在跑的，資料邊產生邊流過去，不需要中間檔案。
    • 講得精確一點：pipe 把左邊 process 的標準輸出（fd 1）接到右邊 process 的標準輸入（fd 0），ch00 page-16 講過這兩個編號。中間的緩衝區由 kernel 提供，所以這是一種 process 之間的溝通方式，也就是這頁標題的 IPC。
  • Filter：讀進輸入、做某種轉換、再輸出的程式。因為輸入輸出都是文字，才能一個接一個串起來。
Filter功能
wc數行數、字數、字元數
grep挑出含有指定字串的行
more一頁一頁顯示，按鍵才往下捲
sort把行照字母或數字排序

page-48#

Examples of Filter & Pipe#

指令做什麼
ls -la | more列出所有檔案（含隱藏檔與詳細資訊），一頁一頁看
cat file | wc把 file 的內容餵給 wc，算出行數、字數、字元數
man ksh | grep "history"在 ksh 的手冊裡找出含 history 的行
ls -l | grep "bowman" | wc串兩層：先挑出含 bowman 的行，再數有幾行
who | sort > current_userswho 列出目前登入的使用者，排序後寫進 current_users 這個檔案

最後一個例子裡的 > 不是 pipe，是 redirection（重導向）：pipe 把輸出接給另一支程式，> 把輸出寫進檔案。

UNIX philosophy：

  1. Write programs that do one thing and do it well——每支程式只做一件事，做到好。
  2. Write programs that work together——程式之間要能互相搭配。
  3. Write programs that handle text streams, because that is the universal interface——都用文字流當介面。

第三條是前兩條能成立的原因：大家的輸入輸出都是純文字，任意兩支程式就接得起來，不必事先約定格式。ls、grep、wc 的作者彼此不認識，ls -l | grep "bowman" | wc 照樣能跑。

Some System Calls For Process Management#

Call作用
pid = fork()建立一個和 parent 一模一樣的 child。回傳值分辨身分：parent 拿到 child 的 PID，child 拿到 0
pid = waitpid(pid, &statloc, options)等某一個 child 結束，並把它的結束狀態放進 statloc
s = execve(name, argv, environp)用 name 這支程式取代目前 process 的 core image（process 在記憶體裡的內容：程式碼加資料）。argv 是命令列參數，environp 是環境變數
exit(status)結束自己，把 status 交回給 parent，由 parent 的 waitpid 收下

一樣留到 Ch8 細講。

page-51#

Typical Memory Arrangement#

這張圖畫的是 一支 process 的記憶體長什麼樣：縱軸是記憶體位址，最下面是低位址、最上面是高位址（跟 ch00 page-16 那張圖同方向，只是那張還畫了 kernel space，這張只畫 user space）。中間那根長條被切成幾段，每一段放不同種類的東西。

由下往上：

區段放什麼怎麼來的
text程式的機器指令，也就是 ch00 page-16 圖上那些框exec 從程式檔讀進來（Read from program file by exec）
initialized data有給初始值的全域變數與 static 變數，例如 int a = 5;同樣由 exec 從程式檔讀進來，因為初始值 5 就存在檔案裡
un-initialized data（bss）沒給初始值的全域變數與 static 變數，例如 int b;程式檔裡不存內容，只記「要多大」。exec 直接把這塊整個填 0（Initialized to 0 by exec）
heapmalloc() 要來的記憶體程式執行中自己要的，用多少長多少
stack函式呼叫用的：參數、區域變數、return address（ch00 page-16 補充過）每呼叫一層函式就往下長一塊，回來就縮回去
最上面那塊（圖上沒有名字）command-line arguments 和 environment variables，也就是 execve(name, argv, environp) 傳進來的那兩樣（page-49）exec 啟動這支程式時放上去的

中間那塊虛線區#

heap 和 stack 中間那段用虛線框起來、還畫了兩個相對的箭頭，表示 目前沒在用的空白區，留給這兩邊成長：

  • stack 由上往下長：多呼叫一層函式，就往低位址延伸一點。
  • heap 由下往上長：malloc 要更多記憶體，就往高位址延伸一點。

兩邊朝對方長，就不必事先決定誰該分多少——哪邊用得多哪邊就長得多。當然也可能長到撞在一起：遞迴太深把 stack 撐爆就是 stack overflow，heap 要不到空間則是 malloc 回傳 NULL。

一個變數會住在哪#

C 裡的東西住在
函式的程式碼text
int g = 5;（全域，有初始值）initialized data
int g;、static int s;（沒初始值）bss
malloc() 拿到的那塊heap
函式裡的區域變數、參數stack
argv、環境變數最上面那塊

順帶兩個常見誤會：

  • 沒初始值的全域變數保證是 0（exec 清過），但 區域變數不保證——stack 上那塊是前一個函式用剩的垃圾，沒人幫你清。
  • 字串常值（char *s = "hello"; 裡的 "hello"）通常跟 text 放在一起，而且是唯讀的，所以去改它會讓程式當掉。

UNIX File and Directory#

  • File：a sequence of bytes。UNIX 眼中的檔案就是一串 byte，沒有格式、沒有結構；要怎麼解讀是程式自己的事。這正是 page-48「用文字流當通用介面」能成立的底層原因。
  • Directory：a file that includes info on how to find other files。目錄本身也是一個檔案，只是它的內容是一張對照表：檔名 → 去哪裡找這個檔案。目錄裡可以再放目錄，所以整個系統長成一棵樹。

圖就是這棵樹，從根目錄 / 往下長。方框是目錄，橢圓是一般檔案：

路徑裡面是什麼
/vmunixkernel 本身的 binary image（ch00 page-07；現在的 Linux 放在 /boot/vmlinuz-*）
/dev裝置檔，例如 console（終端機）、lp0（印表機）。UNIX 把裝置也當成檔案，用同一套 read／write 操作，就是 ch00 page-25 man section 4 說的 special files
/bin可執行檔，例如 csh
/lib函式庫，例如 libc.a（C 標準函式庫，ch00 page-07 的 library routines）
/usr底下有 include，放 stdio.h 這類標頭檔
/etc系統設定檔，例如 page-22 的 passwd

路徑（path）就是從根一路走下來的那條路，例如 /usr/include/stdio.h。

page-54#

Mount File Systems#

一個 file system 就是某塊儲存空間（一顆磁碟、一個分割區、一支隨身碟）上的一棵獨立目錄樹。 問題是：機器上有好幾塊這種空間，怎麼讓使用者用同一套路徑去存取？

Windows 的答案是分成 C:、D: 各自一棵樹。UNIX 的答案是 mount（掛載）：把另一個 file system 接到現有這棵樹的某個目錄底下，全系統始終只有一棵樹、一個根 /。

兩張圖就是掛載前後的對照：

  • (a) 掛載前：根目錄下有 bin、dev、lib、mnt、usr。mnt 是一個空目錄，準備拿來當 掛載點（mount point）。另一個 file system 此時還在那塊磁碟上，但不在這棵樹裡，碰不到。
  • (b) 掛載後：那個 file system 的整棵樹接到 mnt 這個節點底下，於是它的檔案全都能用 /mnt/... 這種路徑存取。

要注意掛載點原本的內容會被暫時蓋住，等 unmount 之後才會再出現。

page-55#

File Permission：ls -l 的輸出#

一行由左到右是：

欄位例子意思
File typel、-、d第 1 個字元。- 一般檔案、d 目錄、l symbolic link（指向另一個路徑的捷徑，所以第一行後面有 home -> /usr/people/maria/）
Permissionsrwxr-xr-x接下來 9 個字元，見下面
連結數1、2有幾個名字指向這個檔案（page-56 的 link）
Ownertest檔案屬於哪個使用者
Groupuser檔案屬於哪個群組
大小94幾個 byte
Modify dateAug 28 13:42最後修改時間
File namenothing.txt檔名

那 9 個字元#

分成三組，每組三個字元，分別給 owner（擁有者）、group（同群組的人）、world（其他所有人）：

每組裡 r 可讀、w 可寫、x 可執行，沒有該權限就寫 -。三個權限各對應一個數字：r = 4、w = 2、x = 1，一組相加就變成一位數，三組合起來就是 chmod 用的三位數。

chmod 700 file.txt：owner 是 7 = 4+2+1 全開，group 和 world 都是 0，完全不給。

chmod g+rw file.txt：符號寫法，只調整指定的部分。u owner、g group、o other、a 全部；+ 加上、- 拿掉、= 設成剛好這樣。

目錄的 rwx 意思不一樣：r 是可以列出裡面有哪些檔案，w 是可以在裡面新增或刪除檔案，x 是可以進入、可以穿過它去存取底下的東西。

相關指令：chmod 改權限、chown 改擁有者、touch 建立空檔或更新修改時間。

page-56#

Some System Calls For Directory Management#

Call作用
s = mkdir(name, mode)建一個新目錄，mode 是它的權限（page-55 那三位數）
s = rmdir(name)刪掉一個空目錄
s = link(name1, name2)讓 name2 這個名字也指向 name1 那個檔案。同一份資料兩個名字，不是複製
s = unlink(name)從目錄裡刪掉 name 這一筆對照，連結數減 1。減到 0，也就是再也沒有名字指得到這個檔案時，kernel 才真的把內容釋放掉
s = mount(special, name, flag)把 special（那塊儲存空間）掛到 name 這個目錄底下，page-54
s = umount(special)卸載

link 和 unlink 要一起看，重點是 檔案的內容和檔案的名字是兩回事：內容只有一份，名字則是目錄裡的一筆對照（page-53：目錄就是「檔名 → 去哪找」的表），而且可以有好幾個。page-55 的連結數就是在算目前有幾個名字指著同一份內容。

link 幫它多加一個名字，unlink 拿掉其中一個名字。所以 rm 做的其實不是「刪掉檔案」，而是 unlink 掉一個名字；只有在拿掉的是最後一個名字時，那份內容才會真的消失。

Some System Calls For File Management#

Call作用
fd = open(file, how, ...)開啟檔案，回傳 fd（file descriptor，ch00 page-16）。how 指定要讀、要寫還是兩者都要
s = close(fd)關閉一個開著的檔案
n = read(fd, buffer, nbytes)從檔案讀資料進 buffer，回傳實際讀到幾個 byte（ch00 page-16 整頁在拆解這個呼叫）
n = write(fd, buffer, nbytes)把 buffer 裡的資料寫進檔案
position = lseek(fd, offset, whence)移動 file pointer
s = stat(name, &buf)取得檔案的狀態資訊，放進 buf

兩個需要解釋的：

  • file pointer：每個開著的檔案都有一個「目前讀寫到哪裡」的位置，read／write 做完會自動往後移。lseek 讓你直接把它移到別處：offset 是移動量，whence 說明從哪裡算起（檔頭、目前位置、還是檔尾）。有它才能不照順序地讀檔案中間某一段。
  • stat：拿到的就是 page-55 ls -l 顯示的那些——檔案型態、權限、owner、group、大小、時間。ls -l 本身就是對每個檔案呼叫 stat 再排版印出來。
